# 路线图

日期：2026-11-08。只读 MVP 已完成本机小规模主流程，证据和未验证范围见 [M3 记录](validation/m3-mvp.md) 与 [实施计划](PLAN.md)；性能、长期稳定性与发行关卡仍在 M4。后续展示能力按“工作区状态与改动 → 文件二级页面”推进，目前仅确认规划、尚未实现。按验收关卡推进，不给未经测量的工期承诺。

```mermaid
flowchart LR
    M0[M0 技术验证与基线] --> M1[M1 历史浏览与元数据搜索]
    M1 --> M2[M2 分支图与提交详情]
    M2 --> M3[M3 路径历史 统计 更新通知]
    M3 --> M4[M4 日用稳定性与分发]
    M4 --> M5[M5 由使用反馈扩展]
```

| 阶段 | 用户能获得什么 | 主要交付 | 退出条件 |
| --- | --- | --- | --- |
| M0：技术验证 | 确认所选路线可行 | Electron ↔ Rust 薄壳、系统 Git 基线、gix 局部比较、fixture 与资源报告 | 可启动并回收子进程，读取真实仓库首批提交；明确主读取路径与性能风险 |
| M1：历史与搜索闭环 | 打开仓库并用消息和字段筛选查找提交 | 仓库会话、分页列表、引用范围、SQLite 元数据索引、元数据搜索、取消与手动刷新 | 10 万提交仓库无需完整索引即可浏览；部分结果自动合并且锚点稳定；固定快照查询与真实仓库搜索可试用 |
| M2：图与详情 | 看清分支关系和某次改动 | 跨页图布局、提交详情、文件列表、按需 diff、搜索结果定位与返回 | merge / root / 大文件等边界正确；长列表和图同步滚动；搜索与图形上下文往返可用；浏览不改变仓库 |
| M3：完整只读 MVP | 快速回答“最近发生了什么” | 路径历史、活动统计、外部变化通知与点击刷新、交给 Agent、完整主路径验收 | 产品主路径贯通，搜索范围可信；Agent 连续提交不打断当前快照查询，刷新后各数据区一致 |
| M4：可日用版本 | 看清尚未提交的改动、按文件追溯变化，并能可靠地日常使用 | 先推进 P4-09 工作区状态与改动、P4-10 文件二级页面；保留资源优化、恢复、平台分发与既有体验增强 | 新能力按各自完成条件验收；发布仍需达到性能 / 正确性关卡及真实仓库试用要求，平台支持仅按实际验收声明 |
| M5：反馈驱动扩展 | 深入回答日用中反复出现的问题 | 代码增删搜索、跨重命名历史、分支包含关系的进一步分析、worktree 聚合等候选 | 每项有真实使用需求与资源预算，单独评估后排入计划 |

## 三个可交付节点

1. **M1 结束：历史与搜索预览。** 能浏览历史，使用消息与身份 / 日期 / hash 等筛选；图、diff、路径搜索、统计和自动更新通知尚未齐全。
2. **M3 结束：只读 MVP。** 产品主路径完整，供本机日常尝试；性能结果仍需对照预算，不能称稳定发布。
3. **M4 结束：日用候选版本。** 真实试用和目标平台验证通过，记录已知限制与实测数据。

## 实施顺序的理由

2026-11-08 确认的后续顺序是 P4-09 → P4-10：先补齐“还有什么正在修改、尚未提交”，再完善“单个文件如何演变”。两项均保持只读，可先进入本机试用；M4 原有性能、恢复与发行关卡继续保留。切分支、fetch、stash 的执行方式不作为前置条件，也未排入开发任务。本次只更新规划，不启动实现。

先打通真实 Git 数据与 Electron / Rust 通信，才能测首屏与进程成本。按 2026-11-07 用户确认的顺序，历史分页稳定后先交付元数据索引和搜索，用真实仓库尽早验证查找提交的核心价值，不以完整图布局和 diff 为前置条件。随后补齐图与详情，接入搜索定位和返回；路径历史、统计继续复用同一范围、筛选和时间语义。固定快照与手动刷新在 M1 建立，M3 增加外部变化通知。最后处理打包、平台差异与长期运行。

M0 的 gix 比较是局部、限范围的验证。若 CLI 已满足目标或 gix 存在兼容缺口，保留 CLI 推进 M1；记录结论即可，不阻塞产品。所有后续优化都保持查询接口与结果语义一致。

## 进入下一阶段前留下什么

每阶段保存可复现的验证步骤、fixture 标识、实测结果、未解决问题和代码版本。任务完成条件见 [实施计划](PLAN.md)，性能预算与正确性关卡见 [验收方案](VALIDATION.md)。没有测量的指标保持“未测”，不得用预期填写通过。

## 暂不排期

切分支、fetch、stash 等由 App 执行还是交给 Agent，后续再讨论；当前继续保持只读、浏览分支不 checkout。工作区状态展示不等于已经提供这些操作。

暂存 / 提交、merge / rebase、三方冲突解决、PR review、账号与云同步、AI 总结均不进入 M0–M4。Linux 与正式分发渠道待目标平台和实际需求明确后单独排期。
