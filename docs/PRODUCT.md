## 为什么做

Agent 让仓库产生更多 commit。人的主要任务变成快速了解仓库发生了什么：近期有多少变化、哪条提交值得看、谁提交了什么，以及相关分支在哪里。首要目标是打开快、滚动顺、搜索准、分支关系清楚。

需求来自用户在[原对话](chatgpt-conversation://6aee1e91-eb04-83e9-b710-302e29850b14)中的后续澄清。本项目不沿用早期以细粒度暂存、三方合并和评审管理为中心的建议。

## 第一版的完整路径

打开本地仓库 → 看到最近提交、分支和活动统计 → 按作者 / 时间 / 消息 / hash / 路径查找 → 定位提交 → 查看修改文件 → 按需展开只读 diff。

| 能力 | 第一版行为 | 完成标准 |
| --- | --- | --- |
| 打开仓库 | 目录选择、最近仓库、识别普通仓库与 linked worktree | 无需等待完整索引；空仓库、无效目录和 Git 不可用有明确状态 |
| 提交历史 | 虚拟列表、拓扑历史图、摘要、作者、时间、hash、引用标签；标出上次查看后新增的提交 | 连续加载无重复遗漏；图跨页连线连续；分支多时最多画 6 条线，其余收为“+n”（拖宽与展开在 M4） |
| 分支浏览 | 本地分支、远端跟踪分支、标签和 worktree 列表；本地分支相对默认分支的合入状态 | 点击仅改变查看范围；显示当前工作区 HEAD，与所看分支区分；标出各 worktree 检出的分支 |
| 提交搜索 | 完整或缩写 OID、作者、提交者、消息、日期、分支范围 | 支持组合筛选；缩写冲突显示候选；索引不完整时说明覆盖范围 |
| 路径历史 | 文件或目录路径过滤 | 匹配所选路径的变更；第一版不承诺跨重命名追溯 |
| 近期活动 | 今天 / 最近 7 天 / 自定义范围的提交数、按日分布与按 Author 分布 | 明示范围、时区和时间字段；多分支去重；计算中不展示假精确总数；点某天或某个身份即加入对应筛选 |
| 提交详情 | 完整消息、trailer、Author、Committer、时间、父提交、引用与 worktree 位置和改动概览；merge 提交列出带入的提交；文件列表放在第二层 | 信息对应选中 OID；快速切换无旧结果覆盖；打开概览后自动加载“包含它的分支”，加载中显示进度，失败可重试 |
| 只读 diff | 选中文件才加载；root、merge、二进制、大文件有明确定义 | merge 默认相对第一父提交，可切换父提交；截断和无法展示状态可见 |
| 交给 Agent | 按任务生成 prompt：审阅一批提交（上次查看后新增、或从某个提交到最新）、审阅单个提交、解释 merge 带入的改动、撤销提交、修复提交引入的问题、清理已合入的分支、核查失效 worktree；可附补充说明，一键复制 | 只复制文本，不执行命令；事实注明观察时间与 OID；仓库文本放入参考数据段 |
| 外部更新 | 感知 Agent / IDE / 终端的提交和引用变化，固定当前浏览快照 | 提示有更新，点开可按引用看到快进、改写、新建、删除；点击刷新后才切换快照，保持所选提交与滚动锚点 |

元数据搜索在 M1 历史分页稳定后交付，用真实仓库尽早验证消息、身份、日期和 OID 查询；M2 补齐图、详情、diff 与搜索结果的历史定位，M3 补齐路径历史、活动统计和外部变化通知。最终 MVP 仍覆盖以上完整路径。

## 界面与交互

2026-11-07 用户在设计画布上比较多个方向后，确认采用 [CommitScope UI 画布](https://claude.ai/artifact/LssQVaEeGiqB1WdCRn2jDa) 的「v3 · B 细化」页；v1、v2 页仅作历史方案保留。2026-11-09 用户确认同一画布的「v4 · 工作区与文件」页作为 P4-09 至 P4-12 的对照稿，范围见下文「后续展示能力」。画布默认只有所有者可见；其中的提交、作者和数字都是示例数据。实现以本节文字为准，画布用于对照布局和视觉。

主界面是“提交列表 + 提交详情”双栏，不设常驻侧栏，也不做大卡片仪表盘。信息分主次：第一层回答“发生了什么、谁做的、在哪个分支”，文件级改动放到第二层。

应用外层固定在窗口内，顶栏和底部状态栏不随内容滚动。提交列表、搜索结果和详情分别在栏内滚动，触底不继续带动外层页面；打开页长内容同样使用自己的滚动区域。

列表与详情之间的分隔线支持拖动调整左栏宽度，历史和搜索结果共用该宽度；调整时保留选择和滚动位置。默认 400px，在窗口允许时左栏至少 320px、详情至少 360px。分隔线可用键盘左右方向键调整，双击恢复默认宽度。

| 区域 | 内容与交互 |
| --- | --- |
| 顶部 | 仓库名；浏览范围选择器；两个按钮各带一行说明（“仓库”“浏览范围”），当前工作区信息（路径、实际 HEAD 与 worktree 数量）收在仓库弹层里；消息搜索框（⌘K 打开命令面板）与筛选按钮；“有 N 处更新”提示（点开看变化明细）与刷新 |
| 条件行 | 有搜索或筛选时才出现：Author / Committer / 日期 / hash / 路径条件显示为可单独移除的标签，另有添加条件、文本大小写开关和清除全部 |
| 左栏 | 提交列表，每条两行：摘要与引用标签；作者头像、姓名、时间与工作区标记。优先显示一个引用，其余收为 `+N`，悬停可看完整名称；其他 worktree 的 HEAD 指向此提交时显示“工作区 N”，悬停显示名称与路径。按天分组，仅显示日期，不将当前窗口内的部分提交数当作当日总数。左侧细分支图与行严格对齐；merge 提交弱化显示。不常驻显示“HEAD 可达 · 固定快照 · 已载入 N 条”等说明；范围在顶栏选择器表达。上下滚动自动续载，不设历史分页按钮或当前窗口序号；仅在加载、失败、无提交或到达末尾时提示。标出本窗口 HEAD 和被其他 worktree 检出的提交。上次查看后新增的提交带圆点；它们在列表顶部连续时，最后一条之后显示“上次看到这里”分隔线。键盘上下选中，复制 OID。搜索时换成结果列表 |
| 右栏 | 选中提交的详情。头部有引用标签、OID 复制、上一条 / 下一条、标题与完整消息；下面分「概览」（默认）和「文件改动」两个标签页。文件清单与 merge 带入列表仅在存在前页或后页时显示分页栏，单页不显示禁用按钮 |
| 底部 | 细状态栏：核心异常状态（就绪时不显示）、索引进度（只给已处理数量，完成后显示当前范围提交数）、加载 / 错误状态、搜索结果数、“只读快照”与 HEAD 读取时间；不常驻显示历史窗口序号、时间口径或时区 |

「概览」分三块：
- 作者与时间：Author、Committer 各自的姓名、邮箱、时间与原始偏移，两者不同时注明。
- 位置与引用：所在分支及是否为其最新提交；远端跟踪引用是否指向同一提交及其本地记录时间；检出此分支的 worktree；父提交；“包含它的分支”。
- 改动概览：文件数，新增 / 修改 / 删除 / 重命名的数量，增删比例，按目录汇总。不展示具体 diff。

所选提交受尚未载入的更新影响时（如所在分支已被改写），在详情头部显示一行提示；其余数据状态只在顶部“有 N 处更新”里出现。界面一律用时间表述（如“14:32 的状态”），不显示内部 generation 编号。

完整消息下方另有“附加信息”，展示从消息末尾解析出的 trailer（如 Co-Authored-By、Refs），正文不再重复。merge 提交的「概览」以“带入的提交”为主：列出这次合并带进来的提交，汇总文件数、增删和作者分布，并标出各父提交所在分支。

「文件改动」列出文件，点开哪个才加载它的 diff。merge 提交在这里切换对比的父提交，默认第一父提交。长 diff 截断、二进制、LFS 指针、子模块 gitlink、重命名分别给出说明，不自动展开或下载。

改动概览、文件清单的对比基准和 merge 带入的比较分组，只有多个选项时才显示下拉框；单一选项用静态文字显示基准及 OID，根提交注明与空树比较。

浏览范围选择器分组列出：范围（HEAD 可达历史、全部分支）；Worktree（名称、主或 linked、HEAD 指向、路径，标出本窗口）；本地分支（标出 HEAD、被哪个 worktree 检出、合入状态；分组标题写明对比的默认分支）；远端跟踪分支（注明本地记录时间）；标签。选中任一项只改变查看范围；选中 worktree 表示查看它 HEAD 的可达历史，不 checkout，也不改动任何 worktree。 当前工作区信息放在仓库弹层的「当前工作区」一节，展示已打开目录在快照中的路径、主/关联类型、实际检出分支与完整 HEAD OID 和 worktree 数量；快照读取时间显示在底栏。本窗口是关联 worktree 时，仓库按钮的说明写“仓库 · 关联 worktree”。这些信息不复用浏览范围选择器。弹层支持点击外部或 Esc 关闭。

近期活动弹层提供今天 / 近 7 天 / 自定义、提交时间与作者时间切换、按日柱状图和按 Author 的数量分布；点某天或某个身份，即在历史中加入对应条件。搜索时右栏说明命中原因，并提供“在历史中定位”。

其他交互：
- 更新明细：点开“有 N 处更新”，按引用分组列出快进（附新增提交）、改写（被替换的提交数与新旧 OID）、新建、删除（附合入状态）。底部是“刷新到 14:51 的状态”这类按钮；不刷新也可继续看当前状态。
- 分支图：默认显示 6 列，图区 `+N` 表示当前行还有 N 条图线被隐藏，图线与命名分支不一一对应。点击可展开当前浏览范围的全部图线，并提供收起入口；较宽时在列表内横向滚动，保持纵向阅读位置与选择。分支尖端所在行显示分支名；查看全部分支仍需在顶栏选择对应范围。拖宽及悬停或选中高亮继续留在 P4-05。
- 窄窗口（M4）：宽度不足 1100px 时只保留列表，详情从右侧以抽屉覆盖，Esc 关闭；搜索收成图标，worktree 入口和更新提示缩短。
- 筛选弹层：筛选按钮先打开“添加条件”菜单；Author / Committer 从已出现的身份中多选；路径输入提供当前状态下的补全，可选是否包含子目录；提交时间有预设和自定义起止日期（包含起止两天）。
- 定位之后：“在历史中定位”后，顶部横幅说明暂时去掉了哪些条件，并提供“返回 N 个结果”；被定位的提交高亮并滚到可视区。
- 快捷键与命令面板：快捷键说明列出浏览、查找、范围与刷新等常用操作；⌘K 命令面板（跳转到提交、分支、worktree 或执行命令）在 M4 加入。
- 交给 Agent：只在有具体任务的地方出现。提交详情头部的“交给 Agent ▾”菜单列出审阅、解释 merge（仅 merge）、审阅从这里到最新、撤销、修复；列表“上次看到这里”分隔线旁可把新增的提交交给 Agent 审阅；范围菜单只在已合入的本地分支上显示“清理”、在失效 worktree 上显示“核查”。对话框标题就是任务名，用一句话说明要让 Agent 做什么，列出涉及的提交、工作区目录和观察时间，提供补充说明；完整 prompt 默认折叠、可展开编辑，复制后提示“粘贴给你的 Agent”。Agent 动手后，引用变化会照常出现在“有 N 处更新”里。
- 身份头像：颜色由小写邮箱（无邮箱时用姓名）的稳定哈希从 8 色板中选取，同一身份始终同色，文字对比度不低于 4.5:1；缩写规则见画布「身份头像配色」。

输入中文时遵守输入法 composition 状态，不在组词期间触发提交或快捷键。支持文本选择、键盘焦点、深浅主题和系统缩放。搜索结果先以列表显示；“在历史中定位”暂时移除消息、作者、提交者、日期、hash 和路径筛选，在原分支范围与浏览快照中恢复图形上下文，并提供返回搜索结果入口。

**加载与异常状态**：提交列表、搜索结果、详情、文件改动、近期活动和范围选择器等每个显示仓库数据的区域，都要单独表达加载中、空结果、部分完成、失败与重试；一处出错不影响其他区域，已读到的内容保留。画布「加载与异常状态」画板列出了各种情况的示例。切换仓库后取消旧任务；后台索引进度不遮挡历史列表。若提交被改写后已不在最新范围，保留当前快照与已读详情并标明有更新；刷新后若所选 OID 已不在范围，保留已读详情并显示状态，不悄悄改选另一条。

提交详情优先于活动统计等辅助读取；短暂繁忙时保持加载并自动重试，连续失败后才提示“读取暂时繁忙，请稍后重试”，提供手动重试入口，不向用户显示“交互请求已满”之类的调度术语。

元数据索引在历史首屏之后构建，底栏只显示已处理数量和真实状态，不估算未知总量百分比。用户可暂停、继续、取消或重建当前仓库索引；暂停 / 取消保留已完成数据，重新打开不会自动继续用户已停止的任务。正常退出或意外中断的运行任务可在重开同一快照后续建。损坏、缺失、不可写或达到缓存上限不影响已读历史；重建仅清理应用缓存。P1-06 已接入真实元数据搜索，结果覆盖范围与索引状态一致。

外部提交、amend、rebase 和引用删除只更新通知，不自动刷新历史、搜索或统计，也不打断当前快照的查询。点击刷新时复核最新引用，再将这些数据区切换到同一新快照；新数据准备好前保留有明确快照标识的旧视图，不混用新旧结果。筛选变化沿用当前浏览快照；主动切换仓库或分支范围时建立对应的新快照。固定快照不保证对象永远存在，GC 后缺失对象需要显示失效或不完整状态。

顶栏在没有发现更新时不显示检查成功状态或灰点；有变化时显示“有 N 处更新”，检查失败或结果不完整时保留相应提示。“刷新”入口继续保留，不用“仓库已复核”表达后台检查结果。

索引尚未完整时，搜索结果按批次自动合并、去重和排序，始终保留所选 OID，以及视口顶部 OID 和行内偏移形成的滚动锚点；不因新命中插入前面而跳回顶部。覆盖完整前标注“部分结果”，当前第一页仅表示已发现结果的排序，不能宣称是完整范围的最新命中。已覆盖范围内没有命中时显示“尚未找到，搜索中”，完成后才显示最终空结果。

历史列表右缘是时间滑轨（代替纵向滚动条）：显示当前阅读位置附近的一段时间，最新在上、每天等高，长度按附近的提交数自动调整——忙时只看几天、能分辨钟点，闲时覆盖数月；悬停显示该时刻与当天提交数，拖动时列表跟随跳到该时刻之前最近的提交，拖到上下边缘继续向更新或更早滚动，滚轮平移、⌘ 滚轮缩放，键盘可按小时 / 天移动。列表顶部固定显示当前阅读到的日期，点它打开按提交数着色的月历，点某天即跳到当天最后的提交（当天没有提交时跳到之前最近的一次）；不在最新处时日期旁出现“回到最新”，Home 与 ⌘↑ 同效。按本地自然日与 Committer 时间定位，保持当前分支范围、固定快照及分支图，不转换为搜索筛选。滑轨与日历的提交数来自活动统计，统计未完成或只保留最近日期时注明。

## 数据口径

- **浏览范围**：首次默认当前 HEAD 可达历史；空 HEAD 显示空状态。可选某个分支、标签或全部分支。全部分支包含本地分支与远端跟踪分支的可达提交，不自动包含 stash、reflog 或仅标签可达提交；detached HEAD 单独可选。
- **统计范围**：沿用当前浏览快照、分支范围和全部有效筛选，包括消息、作者、提交者、日期、hash、路径及大小写选项，按完整 OID 去重。打开仓库后自动计算顶栏数字，筛选变化和当前快照索引推进时更新，不依赖打开统计弹层；首次计算显示转圈与“统计中…”，已有数字重新计算时保留数字并显示转圈与“更新中…”，部分结果加 `~`。支持耗时筛选时显示计算中或已覆盖数量，不把已加载行数当总数。外部新提交仍在手动刷新浏览快照后计入。
- **时间**：默认以 Committer time 统计和过滤，按设备本地时区分日；最近 7 天含今天和前 6 个自然日。日期范围用本地日界转换的半开区间 `[start, end)`。可切换 Author time，列表、筛选和统计同步标注；详情分别显示两者。详情和搜索结果使用“2026年10月30日 12:04:33（UTC+08:00）”形式的本地时间，时区标注对应所显示时间；提交记录的原始时区在悬停说明中保留，不将原始偏移拼在本地时间后造成误读。
- **身份**：保留原始 Author 和 Committer 的姓名、邮箱。第一版不默认合并别名或套用 mailmap。同一个 Git 身份不能自动推断为某个 Agent / 会话。近期活动的身份分布按原始 Author 姓名与邮箱分组，同样不合并别名；头像只由身份文本生成颜色和缩写，不表示身份类型。
- **顺序**：完整历史采用拓扑优先的确定性顺序；时间不同于拓扑位置，不能仅按时间戳推断父子关系。搜索结果按选定时间降序、完整 OID 作为稳定次序。
- **分支关系**：引用标签表示分支尖端；“包含该提交的分支”在打开提交概览后自动查询，不能为 commit 保存唯一 branch 字段。合入状态以远端默认分支为基准：依次取 origin/HEAD 指向的远端跟踪分支、origin/main、origin/master；仓库没有这些远端跟踪分支时，才退回本地 main、master；都不存在时不显示。远端跟踪分支只反映上次 fetch 的结果（本应用不 fetch），选择器里同时显示它的本地记录时间。基准不随任何 worktree 切换而改变，选择器里写明对比的分支。判断分两步，全程只读：分支尖端能从基准尖端到达，显示“已合入”；否则比对补丁，分支独有的每个提交都能在基准上找到相同补丁（rebase 或 cherry-pick 合并），或分支相对分叉点的整体改动与基准上某个提交的补丁相同（squash 合并），显示“内容已在 origin/main”（按实际基准名，“已合入”同理）。补丁比对忽略提交消息和时间；合并时解决过冲突或另加了改动的 squash 提交可能识别不到。两步都不满足、比对超限或尚未完成时不显示标签，不给“未合入”这类否定结论。第一版只做可达判断，补丁比对在 M4 加入；在此之前，不可达的分支同样不显示标签。“与 origin 一致”只比较本地已有的远端跟踪引用是否指向同一 OID，不 fetch。以上都按当前浏览快照计算。
- **上次查看**：每个仓库和浏览范围在应用数据目录记录用户上次看过的引用快照（内容显示后记录，窗口失焦、关闭或切换范围时更新）。“上次查看后新增”指当前状态可达、上次快照不可达的提交，按 OID 集合比较，不按时间；首次打开不做标记。
- **更新明细**：按引用比较当前浏览状态与最新检查到的状态。旧尖端可从新尖端到达为快进，否则为改写；改写时“被替换的提交数”指旧尖端可达、新尖端不可达的提交数。新建和删除按引用是否存在判断。
- **merge 带入的提交**：第 N 个父提交可达、第一父提交不可达的提交，按拓扑顺序列出；octopus merge 按父提交分组。
- **trailer**：按 Git trailer 规则，只解析消息最后一段；解析结果只做展示，不用于筛选，也不用来推断身份。
- **交给 Agent 的 prompt**：使用界面语言，注明本地引用观察时间与未 fetch；区分本窗口 worktree、浏览分支与实际操作 worktree，按实际基准及其 remote 生成步骤，不假设浏览分支已在当前目录检出。正文仅引用编号，所有仓库来源名称、路径、标题与列表经 JSON 序列化放入带随机分隔标记的参考数据段，操作标识不截断。清理仅在合入状态明确时启用；prune 先核对完整 dry-run 集合，不把全局命令描述成单条清理。多父 merge 按全部父提交分组；空仓库、detached、无基准及未计算字段按实际状态省略或注明未知，不填假零。每个任务只附自己需要的参考数据；任务、入口、模板、变量与上限以 [HANDOFF](HANDOFF.md) 为准。
- **路径与 merge**：路径匹配定义为相对任一父提交存在该路径变化，root 与空树比较；文件列表和 diff 使用用户选定的父提交，默认第一父提交。搜索命中后说明其命中的父提交，避免第二父提交的改动在默认 diff 中消失。
- **搜索入口与组合**：普通输入框仅搜索完整提交消息（标题与正文），不因输入看似 hash 就改为 OID 查询；作者、提交者、日期、hash 和路径使用明确筛选项。不同字段之间取交集（AND），同一身份字段内的多选取并集（OR）；Author 和 Committer 分别筛选，不合并为同一身份字段。
- **文本搜索**：MVP 为字面子串匹配，不解释正则或 Git revision。2026-11-07 用户确认默认不区分消息大小写，可显式打开开关；忽略大小写采用 Unicode default full case folding，不额外做规范化、去重音或 locale 定制，所选身份仍按原始姓名 / 邮箱精确匹配。开关状态参与查询身份，部分与完整索引使用同一 Rust 扫描谓词，中文短词和 Unicode 边界单独验证，见[P1-06 契约](implementation/p1-06-metadata-search.md)。索引暂停 / 故障时显示已有覆盖及实际原因，不把部分无命中说成最终空结果。路径按仓库内字面路径 / 目录匹配，不受消息大小写开关影响，不将用户输入当 pathspec 魔法语法。

### 页面切换与顶栏

P4-09 起，顶栏在仓库按钮之后加入页面切换「提交 / 文件 / 工作区」，快捷键 ⌘1 / ⌘2 / ⌘3；「文件」随 P4-10 加入。提交页仍是默认页，各页保留自己的选择、筛选和滚动位置。提交详情「概览 / 文件改动」的快捷键随之从 ⌘1 / ⌘2 改为 ⌥⌘1 / ⌥⌘2，文件页用 ⌥⌘1 回到文件内容、⌥⌘2 显示或隐藏历史列。

全局后退 / 前进（2026-11-09）：⌘[ / ⌘]、顶栏页面切换左侧的 ← → 按钮和鼠标侧键，在记录过的位置之间来回，按钮悬停时写明去向（如“后退到 提交 92aa8c23”）。只有跳转算一步：跨页面跳转与页面切换、文件页打开另一个文件、打开或关闭某次修改、逐行追溯跳转、打开目录历史；在列表里移动选择、滚动、切换浏览范围和刷新不算。回到某一步时重新读取那个位置，不还原像素级的滚动。提交页处于“从搜索定位到历史”时，⌘[ / ⌘] 仍先用于返回搜索结果和定位。每个仓库最多记 50 步，换仓库时清空。

浏览范围紧跟在页面切换之后，只影响提交页和文件页；在工作区页变淡，但仍可打开。改浏览范围不会把工作区换成别的目录。

搜索沿用一个输入框，框内用前缀写明当前范围；⌘F 在任何页面都聚焦它，⌘K 继续留给 M4 的命令面板。
- 提交页：“提交消息”，即现有的元数据搜索与筛选。
- 文件页（选中文件）：“当前文件”（文件名在面包屑里，长文件名放在这里会挤掉输入框），在已加载的内容里查找，不发新查询。没超过行数上限的文件整个加载，查找覆盖全文；被截断的文件，计数和“没有找到”都写明只查了前 N 行，不让人误以为整个文件里没有。
- 文件页（选中目录）：“目录历史”，搜索提交消息，路径条件固定为这个目录。文件的历史在历史列顶部的筛选框里按提交消息筛选。前缀保持简短，窄窗口下输入框的提示文字仍能完整显示。
- 工作区页：“改动的文件”，按路径过滤左栏。

顶栏位置固定，窗口变窄时按顺序缩减：先缩搜索框，再收近期活动的数字和刷新的文字；更窄时页面切换只留图标和角标，搜索收成按钮（点它或按 ⌘F 展开），快捷键说明收进“⋯”；最后截断仓库名和分支名。仓库、页面切换、浏览范围、“有 N 处更新”和刷新始终可见，悬停说明给出完整文字。

### 工作区状态与改动

顶栏「工作区」切换项用角标表示状态：有改动时显示文件数，有冲突时显示“冲突 N”，完整读取且没有改动时显示绿点。首次读取时不显示数字；读取后文件又变化时保留上次的数字并改为空心角标；结果不完整时数字是下限（如“2000+”）；读取失败显示“?”。悬停说明给出目录、实际分支和读取时间，读屏文字为“工作区干净”或“工作区：有 N 个文件改动”。浏览范围不是工作区所在分支时，切换项写出工作区的分支（如“工作区 · main”），detached 时写短 OID；两者一致时不写。bare 仓库没有工作区，这一项置灰不可点。

工作区页左栏按已暂存、未暂存、未跟踪和冲突分组列出文件，右侧显示所选文件在这一组里的 diff 或内容。已暂存对比 HEAD 与 index，未暂存对比 index 与工作区；同一文件可同时有两类改动，总文件数按路径去重，右侧注明另一组也有改动。未跟踪文件计入改动，忽略文件默认不列出。冲突仅展示状态和带冲突标记的内容，未跟踪文件提供有界内容预览，二进制 / 大文件明确说明。

工作区状态对应本窗口实际打开的目录和实际分支，与当前浏览的分支范围区分。Agent 修改文件后可自动复核这部分状态，并保留手动刷新；标明观察时间，不改变固定历史快照、提交选择或滚动位置。仅完整读取并确认无改动时才算“干净”；初次读取、失败、过期或不完整状态要明确表达。

### 文件二级页面

提交列表继续作为默认主界面，文件页是并列的第二个页面：从左到右是目录树、可开关的历史列和文件内容（2026-11-09 按试用反馈修订，取代「内容 / 历史」两个标签页）。目录树展示选定分支或提交的已提交快照，不含工作区改动，查看其他分支无需切换工作区；全部分支没有唯一目录树，需要先选一个树的版本。文件历史默认查询该版本的可达历史，不混入实时工作区内容。

在目录树里点文件，右侧显示该版本的完整文本（纯文本，有行数上限）；二进制、LFS 指针、子模块、符号链接和超限文件给出说明。历史列由子标题行的“历史”开关（⌥⌘2）打开，状态会记住；它列出修改过这个路径的提交，顶部可按提交消息筛选，列表获得焦点时 ↑ / ↓ 逐条切换。选中一条提交，这次提交对文件的修改从左侧（历史列一侧）滑入、盖住文件，标题栏可在“改动 / 这一版的文件”之间切换，后者只显示文件在那次提交时的全文、不做对比，也不改变目录树版本；修改视图左上角的“← 文件名”（或 Esc、⌥⌘1）让文件从右侧滑回，停在原来的滚动位置。merge 可切换比较父提交；diff 标题行显示“第 n / N 处改动”，可上下跳转。目录树和历史列的宽度可以拖动调整并记住，双击边缘恢复默认。点击文件夹只展开或收起（路径面包屑里的文件夹段也一样，只在目录树里展开并定位），保留右侧正在查看的内容，不自动查询目录历史；目录旁的历史按钮在悬停或键盘聚焦时显示，点击后在历史列查看目录内的变更历史，选中一条提交时右侧列出这个目录下改动的文件，每个文件可就地展开它的 diff。目录没有内容视图。

提交详情的文件行可“在文件页打开”这个文件，显示目录树版本里的内容（这次提交删除的文件改为打开它的历史并选中这次修改；之后被改名或删除、当前版本里已没有的文件，改为在它的历史里选中这次提交并显示“这一版的文件”，目录树版本不变，横幅注明）；工作区改动列表可进入对应文件历史；文件历史可返回完整提交，往返保留选择、筛选和阅读位置。跨页面跳转后，目标页面顶部提示从哪里来并给出返回按钮（如“← 回到 app.ts”“← 回到提交 92aa8c23”“← 回到工作区”），回到来源页面或手动关闭后提示消失。删除文件可从删除记录或旧树进入，没有历史的未跟踪文件显示空状态。首版复用现有字面路径查询，明确不跨重命名追溯；跨重命名历史和任意双版本比较继续作为后续候选。

### diff 显示增强

P4-11 为所有 diff（提交详情、文件历史、工作区）加一个“显示”菜单。选择对所有 diff 生效，下次打开仍然有效：
- 排列：上下合并或左右并排（⌥D 切换）。左右并排时，成对的删除 / 新增行标出行内改动的部分。
- 范围：只看改动（前后各 3 行）或完整文件（⌥F 切换）；超过行数上限的文件不提供完整文件。
- 自动换行（⌥Z）。

diff 标题行只外露增删数、merge 的父提交选择和“第 n / N 处”。左右并排时历史列仍是固定的一列，不再收成悬浮列表；需要更宽时可以收起历史列或拖窄目录树。

P4-11 同时为内容页和 diff 加语法高亮：按文件扩展名识别语言，只改变颜色、不改变文本；大文件或无法识别时显示纯文本。

### 逐行追溯

P4-12 在文件页「内容」加“逐行追溯”开关（⌥B）。左侧按块显示每段内容最后由哪个提交修改，写日期和作者，颜色越深越新。悬停显示提交摘要、这一块的行范围和该提交在本文件的增删。单击打开历史列并选中这个提交，这次修改从左侧滑入，定位到包含该行的改动并高亮那一行；左上角“← 文件名 第 N 行”返回文件，那一行闪一下。来自整文件改名之前的行，历史列顶部提示改名前的路径，点它查看那个路径的历史；悬停卡片只展示信息、没有按钮；要看完整提交，在修改视图里点“查看完整提交”。

追溯跟随整个文件的改名（Git 默认行为），文件历史仍按字面路径；某一块来自改名之前时，悬停卡片写出当时的路径，定位时打开那个路径的历史。大文件不提供逐行追溯并说明原因；结果逐步显示，可以取消。

## 第一版边界与后续假设

当前版本只负责展示，具体的 Git 操作通过“交给 Agent”复制 prompt，由用户交给外部 Agent 完成；App 不直接调用 Agent，也不执行 Git 写操作。第一版不做写操作、冲突解决器、完整 review 工作流、PR / 账号集成、云同步、AI 总结、Agent 身份推断和自动远程更新。远端跟踪分支展示的是本地已有引用，注明更新时间。后续操作能力按上节另行讨论，当前分工不作为永久排除 App 基础操作的决定。

按代码增删内容搜索、跨重命名历史、跨仓库活动、多 worktree 聚合视图和包含关系的进一步分析放到后续阶段。Linux、正式命名和商业模式不阻塞首个 macOS 闭环；Windows 是计划中的第二验收平台。

浅克隆、缺失对象与 partial clone 必须显示数据边界；MVP 不自动补拉对象。子模块作为独立仓库打开，父仓库详情只显示 gitlink 变化。bare 仓库支持在 M0 验证，若暂不支持，明确提示而非误报为空仓库。
