## 为什么做

Agent 让仓库产生更多 commit。人的主要任务变成快速了解仓库发生了什么：近期有多少变化、哪条提交值得看、谁提交了什么，以及相关分支在哪里。首要目标是打开快、滚动顺、搜索准、分支关系清楚。

需求来自用户在[原对话](chatgpt-conversation://6aee1e91-eb04-83e9-b710-302e29850b14)中的后续澄清。本项目不沿用早期以细粒度暂存、三方合并和评审管理为中心的建议。

2026-11-17 补充：核心用户场景是不打开传统 IDE / 编辑器、主要对着 Agent 终端进行 Vibe Coding，以 CherryPeek 作为查看仓库状态与把关收口的唯一图形界面。写代码、改历史与复杂排障首选“交给 Agent”；审阅把关、确定性收口（Commit / 快进合入主线 / Push）与零中间态三栏轻量冲突点选作为后续闭环与次选路径，阶段规划见 [路线图](ROADMAP.md)。

## 第一版的完整路径

打开本地仓库 → 看到最近提交、分支和活动统计 → 按作者 / 时间 / 消息 / hash / 路径查找 → 定位提交 → 查看修改文件 → 按需展开只读 diff。

| 能力 | 第一版行为 | 完成标准 |
| --- | --- | --- |
| 打开仓库 | 目录选择、最近仓库、识别普通仓库与 linked worktree | 无需等待完整索引；空仓库、无效目录和 Git 不可用有明确状态 |
| 提交历史 | 虚拟列表、拓扑历史图、摘要、作者、时间、hash、引用标签；标出上次查看后新增的提交 | 连续加载无重复遗漏；图跨页连线连续；分支多时最多画 6 条线，其余收为“+n”（拖宽与展开在 M4） |
| 分支浏览 | 本地分支、远端跟踪分支、标签和 worktree 列表；本地分支相对默认分支的合入状态 | 点击仅改变查看范围；显示当前工作区 HEAD，与所看分支区分；标出各 worktree 检出的分支 |
| 提交搜索 | 完整或缩写 OID、作者、提交者、消息、日期、分支范围 | 支持组合筛选；缩写冲突显示候选；索引不完整时说明覆盖范围 |
| 路径历史 | 文件或目录路径过滤 | 匹配所选路径的变更；第一版不承诺跨重命名追溯 |
| 近期活动 | 今天 / 最近 7 天 / 自定义范围的提交数、按日分布与按 Author 分布 | 明示范围、时区和时间字段；多分支去重；计算中不展示假精确总数；点某天或某个身份即加入对应筛选 |
| 提交详情 | 完整消息、trailer、Author、Committer、时间、父提交、引用与 worktree 位置和改动概览；merge 提交列出带入的提交；文件列表放在第二层 | 信息对应选中 OID；快速切换无旧结果覆盖；打开概览后自动加载“包含它的分支”，加载中显示进度，失败可重试 |
| 只读 diff | 选中文件才加载；root、merge、二进制、大文件有明确定义 | merge 默认相对第一父提交，可切换父提交；截断和无法展示状态可见 |
| 交给 Agent | 按任务生成 prompt：审阅一批提交（上次查看后新增、或从某个提交到最新）、审阅单个提交、解释 merge 带入的改动、撤销提交、修复提交引入的问题、清理已合入的分支、核查失效 worktree；可附补充说明，一键复制 | 只复制文本，不执行命令；事实注明观察时间与 OID；仓库文本放入参考数据段 |
| 外部更新 | 感知 Agent / IDE / 终端的提交和引用变化，固定当前浏览快照 | 提示有更新，点开可按引用看到快进、改写、新建、删除；点击刷新后才切换快照，保持所选提交与滚动锚点 |

元数据搜索在 M1 历史分页稳定后交付，用真实仓库尽早验证消息、身份、日期和 OID 查询；M2 补齐图、详情、diff 与搜索结果的历史定位，M3 补齐路径历史、活动统计和外部变化通知。最终 MVP 仍覆盖以上完整路径。

## 界面与交互

2026-11-07 用户在设计画布上比较多个方向后，确认采用 CommitScope UI 画布（未公开） 的「v3 · B 细化」页；v1、v2 页仅作历史方案保留。2026-11-09 用户确认同一画布的「v4 · 工作区与文件」页作为 P4-09 至 P4-12 的对照稿，范围见下文「后续展示能力」。画布默认只有所有者可见；其中的提交、作者和数字都是示例数据。实现以本节文字为准，画布用于对照布局和视觉。

主界面是“提交列表 + 提交详情”双栏，不设常驻侧栏，也不做大卡片仪表盘。信息分主次：第一层回答“发生了什么、谁做的、在哪个分支”，文件级改动放到第二层。

应用外层固定在窗口内，顶栏和底部状态栏不随内容滚动。提交列表、搜索结果和详情分别在栏内滚动，触底不继续带动外层页面；打开页长内容同样使用自己的滚动区域。

列表与详情之间的分隔线支持拖动调整左栏宽度，历史和搜索结果共用该宽度；调整时保留选择和滚动位置。默认 400px，在窗口允许时左栏至少 320px、详情至少 360px。分隔线可用键盘左右方向键调整，双击恢复默认宽度。

| 区域 | 内容与交互 |
| --- | --- |
| 顶部 | 仓库名；浏览范围选择器；两个按钮各带一行说明（“仓库”“浏览范围”），当前工作区信息（路径、实际 HEAD 与 worktree 数量）收在仓库弹层里；消息搜索框（⌘K 打开命令面板）与筛选按钮；“有 N 处更新”提示（点开看变化明细）与刷新 |
| 条件行 | 有搜索或筛选时才出现：Author / Committer / 日期 / hash / 路径条件显示为可单独移除的标签，另有添加条件、文本大小写开关和清除全部 |
| 左栏 | 提交列表，每条两行：摘要与引用标签；作者头像、姓名、时间与工作区标记。优先显示一个引用，其余收为 `+N`，悬停可看完整名称；其他 worktree 的 HEAD 指向此提交时显示“工作区 N”，悬停显示名称与路径。按天分组，仅显示日期，不将当前窗口内的部分提交数当作当日总数。左侧细分支图与行严格对齐；merge 提交弱化显示。不常驻显示“HEAD 可达 · 固定快照 · 已载入 N 条”等说明；范围在顶栏选择器表达。上下滚动自动续载，不设历史分页按钮或当前窗口序号；仅在加载、失败、无提交或到达末尾时提示。标出本窗口 HEAD 和被其他 worktree 检出的提交。上次查看后新增的提交带圆点；它们在列表顶部连续时，最后一条之后显示“上次看到这里”分隔线。键盘上下选中，复制 OID。搜索时换成结果列表 |
| 右栏 | 选中提交的详情。头部：有引用标签时单独一行；标题与“交给 Agent”、OID 复制、上一条 / 下一条同一行（窄时按钮移到标题上方）；下面是完整消息（正文超过 6 行时折叠，“展开全文（共 N 行）”展开）；下面是一页往下滚：先是紧凑的「概览」（作者、父提交、包含它的分支、改动，每项一行，merge 另有带入的提交），再是「文件改动」列表（2026-11-09 用户确认，取代「概览 / 文件改动」两个标签页；merge 的父提交只在文件改动标题处切换一次，概览注明与哪个父提交比较；改动概览末尾“查看文件列表”滚到下方；换提交时回到顶部）。文件清单一页超过 30 个文件时折叠，末尾“还有 N 个文件”展开，正在展开 diff 的文件不会被收起；折叠时不显示“下一页”，展开后才能翻页，避免漏看中间的文件；换提交时恢复折叠。文件清单与 merge 带入列表仅在存在前页或后页时显示分页栏，单页不显示禁用按钮 |
| 底部 | 细状态栏：核心异常状态（就绪时不显示）、索引进度（只给已处理数量，完成后显示当前范围提交数）、加载 / 错误状态、搜索结果数、“只读快照”与 HEAD 读取时间；不常驻显示历史窗口序号、时间口径或时区 |

「概览」是一张紧凑的键值表（2026-11-09 按试用反馈压缩，让文件改动出现在第一屏），每项一行：
- 作者：头像、姓名、邮箱、时间与原始偏移在同一行；与提交者相同时注明“也是提交者”，不同时另起“提交者”一行。
- 父提交：短 OID（悬停看完整 OID）与标题，已载入时点标题选中它；merge 逐个标“父 N”。
- 其他 worktree：只在其他 worktree 的 HEAD 正是这个提交时出现。
- 包含它的分支：本地的 main / master 在前，其次其他本地分支、远程的主线、其他远程分支和标签；超过 8 个时折叠，末尾“还有 N 个分支”展开，换提交时恢复折叠。
- 改动：文件数、增删数，只列数量不为 0 的类型（新增 / 修改 / 删除 / 重命名 / 复制 / 类型变化 / 二进制 / 子模块引用），目录多于一个时再列文件最多的 5 个目录，末尾“查看文件”滚到下方。

所在引用与本窗口 HEAD 由页头的引用标签表达，完整 OID 在页头的复制按钮里，概览不再重复。

所选提交受尚未载入的更新影响时（如所在分支已被改写），在详情头部显示一行提示；其余数据状态只在顶部“有 N 处更新”里出现。界面一律用时间表述（如“14:32 的状态”），不显示内部 generation 编号。

完整消息下方紧接着列出从消息末尾解析出的 trailer（如 Co-Authored-By、Refs），不加外框，正文不再重复。merge 提交的「概览」以“带入的提交”为主：列出这次合并带进来的提交，汇总文件数、增删和作者分布，并标出各父提交所在分支。

「文件改动」列出文件，点开哪个才加载它的 diff。merge 提交在这里切换对比的父提交，默认第一父提交。长 diff 截断、二进制、LFS 指针、子模块 gitlink、重命名分别给出说明，不自动展开或下载。

改动概览、文件清单的对比基准和 merge 带入的比较分组，只有多个选项时才显示下拉框；单一选项用静态文字显示基准及 OID，根提交注明与空树比较。

浏览范围选择器分组列出：范围（HEAD 可达历史、全部分支）；Worktree（名称、主或 linked、HEAD 指向、路径，标出本窗口）；本地分支（标出 HEAD、被哪个 worktree 检出、合入状态；分组标题写明对比的默认分支）；远端跟踪分支（注明本地记录时间）；标签。选中任一项只改变查看范围；选中 worktree 表示查看它 HEAD 的可达历史，不 checkout，也不改动任何 worktree。 当前工作区信息放在仓库弹层的「当前工作区」一节，展示已打开目录在快照中的路径、主/关联类型、实际检出分支与完整 HEAD OID 和 worktree 数量；快照读取时间显示在底栏。本窗口是关联 worktree 时，仓库按钮的说明写“仓库 · 关联 worktree”。这些信息不复用浏览范围选择器。弹层支持点击外部或 Esc 关闭。

近期活动弹层提供今天 / 近 7 天 / 自定义、提交时间与作者时间切换、按日柱状图和按 Author 的数量分布；点某天或某个身份，即在历史中加入对应条件。搜索时右栏说明命中原因，并提供“在历史中定位”。

其他交互：
- 更新明细：点开“有 N 处更新”，按引用分组列出快进（附新增提交）、改写（被替换的提交数与新旧 OID）、新建、删除（附合入状态）。底部是“刷新到 14:51 的状态”这类按钮；不刷新也可继续看当前状态。
- 分支图：默认最多显示 6 列，图区右缘可拖动为 4–12 列，也可用左右键逐列调整、双击恢复默认。图区 `+N` 随当前宽度显示隐藏图线数量；点击可展开当前范围全部图线，收起恢复自定义列数。较宽时只在列表内横向滚动，保持纵向阅读位置与选择。悬停提交时突出它的第一父主线和真实换道连线，移开后恢复选中提交的主线，其余线透明度 0.4；向上追踪在分叉处停止，不因同色或复用列号而误亮无关线。高亮只覆盖当前已加载图数据，不触发查询。图线与命名分支不一一对应，分支尖端所在行显示分支名；查看全部分支仍需在顶栏选择对应范围。
- 窄窗口（P4-06）：宽度不足 1100px 时列表占满，点击提交或在列表按 Enter 从右侧打开 560px 详情抽屉；方向键仍可先浏览选择，不自动弹出。顶部提供上一个 / 下一个和关闭，Esc 或遮罩关闭后焦点回到列表。搜索结果与命令定位同样支持。跨宽窄断点时收起抽屉，保留所选提交、列表滚动位置及宽屏分栏宽度。顶栏沿用 P4-09 缩减规则，仍可切换页面和搜索。
- 筛选弹层：筛选按钮先打开“添加条件”菜单；新增批次可按“上次更新”或“自上次查看新增”拓扑范围一键过滤（不依赖时间排序）；Author / Committer 从已出现的身份中多选；路径输入提供当前状态下的补全，可选是否包含子目录；提交时间提供近 1 / 3 / 6 / 12 小时、今天、近 7 天、近 30 天预设以及“按天 / 精确到时分”起止输入（精确到分钟）。生效中的筛选在列表上方以可单独关闭的芯片条显示，并支持一键带入统计页或清空全部。
- 定位之后：“在历史中定位”后，顶部横幅说明暂时去掉了哪些条件，并提供“返回 N 个结果”；被定位的提交高亮并滚到可视区。
- 快捷键与命令面板：快捷键说明列出浏览、查找、范围与刷新等常用操作；⌘K / Ctrl+K 打开快速跳转，支持提交 hash、分支、标签、worktree、打开仓库、切换页面与复制当前提交。至少 4 位的短 hash 由 Git 解析，再在当前固定范围内定位；不存在或不唯一时提示补全，不依赖索引进度。方向键选择，回车执行，Esc 或点击外部关闭并恢复焦点；输入法组词期间不触发。
- 交给 Agent：只在有具体任务的地方出现。提交详情头部的“交给 Agent ▾”菜单列出审阅、解释 merge（仅 merge）、审阅从这里到最新（不限当前已加载页位置，超过百条由内核计算完整边界）、撤销、修复；列表“上次看到这里”分隔线、超过首屏的新增提示条以及更新完成通知均提供“筛选”“查看统计”与“交给 Agent”，按完整拓扑范围与首尾代表性摘要生成安全 prompt（上限扩展至 256 KiB）；范围菜单只在已合入的本地分支上显示“清理”、在失效 worktree 上显示“核查”。对话框标题就是任务名，用一句话说明要让 Agent 做什么，列出涉及的提交、工作区目录和观察时间，提供补充说明；完整 prompt 默认折叠、可展开编辑，复制后提示“粘贴给你的 Agent”。Agent 动手后，引用变化会照常出现在“有 N 处更新”里。
- 身份头像：颜色由小写邮箱（无邮箱时用姓名）的稳定哈希从 8 色板中选取，同一身份始终同色，文字对比度不低于 4.5:1；缩写规则见画布「身份头像配色」。

输入中文时遵守输入法 composition 状态，不在组词期间触发提交或快捷键。支持文本选择、键盘焦点、深浅主题和系统缩放。搜索结果先以列表显示；“在历史中定位”暂时移除消息、作者、提交者、日期、hash 和路径筛选，在原分支范围与浏览快照中恢复图形上下文，并提供返回搜索结果入口。

**加载与异常状态**：提交列表、搜索结果、详情、文件改动、近期活动和范围选择器等每个显示仓库数据的区域，都要单独表达加载中、空结果、部分完成、失败与重试；一处出错不影响其他区域，已读到的内容保留。画布「加载与异常状态」画板列出了各种情况的示例。切换仓库后取消旧任务；后台索引进度不遮挡历史列表。若提交被改写后已不在最新范围，保留当前快照与已读详情并标明有更新；刷新后若所选 OID 已不在范围，保留已读详情并显示状态，不悄悄改选另一条。

提交详情优先于活动统计等辅助读取；短暂繁忙时保持加载并自动重试，连续失败后才提示“读取暂时繁忙，请稍后重试”，提供手动重试入口，不向用户显示“交互请求已满”之类的调度术语。

元数据索引在历史首屏之后构建，底栏只显示已处理数量和真实状态，不估算未知总量百分比。用户可暂停、继续、取消或重建当前仓库索引；暂停 / 取消保留已完成数据，重新打开不会自动继续用户已停止的任务。正常退出或意外中断的运行任务可在重开同一快照后续建。损坏、缺失、不可写或达到缓存上限不影响已读历史；重建仅清理应用缓存。P1-06 已接入真实元数据搜索，结果覆盖范围与索引状态一致。

外部提交、amend、rebase 和引用删除只更新通知，不自动刷新历史、搜索或统计，也不打断当前快照的查询。点击刷新时复核最新引用，再将这些数据区切换到同一新快照；新数据准备好前保留有明确快照标识的旧视图，不混用新旧结果。筛选变化沿用当前浏览快照；主动切换仓库或分支范围时建立对应的新快照。固定快照不保证对象永远存在，GC 后缺失对象需要显示失效或不完整状态。

顶栏在没有发现更新时不显示检查成功状态或灰点；有变化时显示“有 N 处更新”，检查失败或结果不完整时保留相应提示。“刷新”入口继续保留，不用“仓库已复核”表达后台检查结果。

索引尚未完整时，搜索结果按批次自动合并、去重和排序，始终保留所选 OID，以及视口顶部 OID 和行内偏移形成的滚动锚点；不因新命中插入前面而跳回顶部。覆盖完整前标注“部分结果”，当前第一页仅表示已发现结果的排序，不能宣称是完整范围的最新命中。已覆盖范围内没有命中时显示“尚未找到，搜索中”，完成后才显示最终空结果。

历史列表右缘是时间滑轨（代替纵向滚动条）：显示当前阅读位置附近的一段时间，最新在上、每天等高，长度按附近的提交数自动调整——忙时只看几天、能分辨钟点，闲时覆盖数月；悬停显示该时刻与当天提交数，拖动时列表跟随跳到该时刻之前最近的提交，拖到上下边缘继续向更新或更早滚动，滚轮平移、⌘ 滚轮缩放，键盘可按小时 / 天移动。列表顶部固定显示当前阅读到的日期，点它打开按提交数着色的月历，点某天即跳到当天最后的提交（当天没有提交时跳到之前最近的一次）；不在最新处时日期旁出现“回到最新”，Home 与 ⌘↑ 同效。按本地自然日与 Committer 时间定位，保持当前分支范围、固定快照及分支图，不转换为搜索筛选。滑轨与日历的提交数来自活动统计，统计未完成或只保留最近日期时注明。

## 数据口径

- **浏览范围**：首次默认当前 HEAD 可达历史；空 HEAD 显示空状态。可选某个分支、标签或全部分支。全部分支包含本地分支与远端跟踪分支的可达提交，不自动包含 stash、reflog 或仅标签可达提交；detached HEAD 单独可选。
- **统计范围**：沿用当前浏览快照、分支范围和全部有效筛选，包括消息、作者、提交者、日期、hash、路径及大小写选项，按完整 OID 去重。打开仓库后自动计算顶栏数字，筛选变化和当前快照索引推进时更新，不依赖打开统计弹层；首次计算显示转圈与“统计中…”，已有数字重新计算时保留数字并显示转圈与“更新中…”，部分结果加 `~`。支持耗时筛选时显示计算中或已覆盖数量，不把已加载行数当总数。外部新提交仍在手动刷新浏览快照后计入。
- **时间**：默认以 Committer time 统计和过滤，按设备本地时区分日；最近 7 天含今天和前 6 个自然日。日期范围用本地日界转换的半开区间 `[start, end)`。可切换 Author time，列表、筛选和统计同步标注；详情分别显示两者。详情和搜索结果使用“2026年10月30日 12:04:33（UTC+08:00）”形式的本地时间，时区标注对应所显示时间；提交记录的原始时区在悬停说明中保留，不将原始偏移拼在本地时间后造成误读。
- **身份**：保留原始 Author 和 Committer 的姓名、邮箱。第一版不默认合并别名或套用 mailmap。同一个 Git 身份不能自动推断为某个 Agent / 会话。近期活动的身份分布按原始 Author 姓名与邮箱分组，同样不合并别名；头像只由身份文本生成颜色和缩写，不表示身份类型。
- **顺序**：完整历史采用拓扑优先的确定性顺序；时间不同于拓扑位置，不能仅按时间戳推断父子关系。搜索结果按选定时间降序、完整 OID 作为稳定次序。
- **分支关系**：引用标签表示分支尖端；“包含该提交的分支”在打开提交概览后自动查询，不能为 commit 保存唯一 branch 字段。合入状态以远端默认分支为基准：依次取 origin/HEAD 指向的远端跟踪分支、origin/main、origin/master；仓库没有这些远端跟踪分支时，才退回本地 main、master；都不存在时不显示。远端跟踪分支只反映上次 fetch 的结果（本应用不自动 fetch；手动 fetch 见「基础操作」，待实现），选择器里同时显示它的本地记录时间。基准不随任何 worktree 切换而改变，选择器里写明对比的分支。判断分两步，全程只读：分支尖端能从基准尖端到达，显示“已合入”；否则比对补丁，分支独有的每个提交都能在基准上找到相同补丁（rebase 或 cherry-pick 合并），或分支相对分叉点的整体改动与基准上某个提交的补丁相同（squash 合并），显示“内容已在 origin/main”（按实际基准名，“已合入”同理）。补丁比对忽略提交消息和时间；合并时解决过冲突或另加了改动的 squash 提交可能识别不到。两步都不满足、比对超限或尚未完成时不显示标签，不给“未合入”这类否定结论。P4-08 已接入 `git patch-id --stable` 比对，忽略空白和行号；每次最多比较 512 个两侧独有提交、单侧 8 MiB 补丁。空补丁不作为匹配证据；分支包含 merge 时只尝试整体补丁。标签表示历史中存在等价补丁，清理前仍需重新核对当前内容及后续撤销。“与 origin 一致”只比较本地已有的远端跟踪引用是否指向同一 OID，不 fetch。以上都按当前浏览快照计算。
- **上次查看**：每个仓库和浏览范围在应用数据目录记录用户上次看过的引用快照（内容显示后记录，窗口失焦、关闭或切换范围时更新）。“上次查看后新增”指当前状态可达、上次快照不可达的提交，按 OID 集合比较，不按时间；首次打开不做标记。
- **更新明细**：按引用比较当前浏览状态与最新检查到的状态。旧尖端可从新尖端到达为快进，否则为改写；改写时“被替换的提交数”指旧尖端可达、新尖端不可达的提交数。新建和删除按引用是否存在判断。
- **merge 带入的提交**：第 N 个父提交可达、第一父提交不可达的提交，按拓扑顺序列出；octopus merge 按父提交分组。
- **trailer**：按 Git trailer 规则，只解析消息最后一段；解析结果只做展示，不用于筛选，也不用来推断身份。
- **交给 Agent 的 prompt**：使用界面语言，注明本地引用观察时间与未 fetch；区分本窗口 worktree、浏览分支与实际操作 worktree，按实际基准及其 remote 生成步骤，不假设浏览分支已在当前目录检出。正文仅引用编号，所有仓库来源名称、路径、标题与列表经 JSON 序列化放入带随机分隔标记的参考数据段，操作标识不截断。清理仅在合入状态明确时启用；prune 先核对完整 dry-run 集合，不把全局命令描述成单条清理。多父 merge 按全部父提交分组；空仓库、detached、无基准及未计算字段按实际状态省略或注明未知，不填假零。每个任务只附自己需要的参考数据；任务、入口、模板、变量与上限以 [HANDOFF](HANDOFF.md) 为准。
- **路径与 merge**：路径匹配定义为相对任一父提交存在该路径变化，root 与空树比较；文件列表和 diff 使用用户选定的父提交，默认第一父提交。搜索命中后说明其命中的父提交，避免第二父提交的改动在默认 diff 中消失。
- **搜索入口与组合**：普通输入框仅搜索完整提交消息（标题与正文），不因输入看似 hash 就改为 OID 查询；作者、提交者、日期、hash 和路径使用明确筛选项。不同字段之间取交集（AND），同一身份字段内的多选取并集（OR）；Author 和 Committer 分别筛选，不合并为同一身份字段。
- **文本搜索**：MVP 为字面子串匹配，不解释正则或 Git revision。2026-11-07 用户确认默认不区分消息大小写，可显式打开开关；忽略大小写采用 Unicode default full case folding，不额外做规范化、去重音或 locale 定制，所选身份仍按原始姓名 / 邮箱精确匹配。开关状态参与查询身份，部分与完整索引使用同一 Rust 扫描谓词，中文短词和 Unicode 边界单独验证，见[P1-06 契约](implementation/p1-06-metadata-search.md)。索引暂停 / 故障时显示已有覆盖及实际原因，不把部分无命中说成最终空结果。路径按仓库内字面路径 / 目录匹配，不受消息大小写开关影响，不将用户输入当 pathspec 魔法语法。

### 页面切换与顶栏

P4-09 起，顶栏在仓库按钮之后加入页面切换「提交 / 文件 / 工作区」，快捷键 ⌘1 / ⌘2 / ⌘3；「文件」随 P4-10 加入。提交页仍是默认页，各页保留自己的选择、筛选和滚动位置。提交详情「概览 / 文件改动」的快捷键随之从 ⌘1 / ⌘2 改为 ⌥⌘1 / ⌥⌘2。

快捷键规则（2026-11-09 统一，每个按键在所有页面含义相同）：⌘ + 数字切换页面；⌥⌘1 / ⌥⌘2 选右侧的第一 / 第二视图（提交页滚到“概览 / 文件改动”，文件页“文件 / 修改”，⌥⌘2 打开所选提交的修改，没选时打开最新一条）；⌥ + 字母开关显示选项（⌥H 历史列、⌥B 逐行追溯、⌥D / ⌥F / ⌥Z diff 显示）；⌘[ / ⌘] 始终是后退 / 前进；⌘L 把所选搜索结果定位到完整历史（原 ⌘]），定位后 ⌘[ 回到搜索结果；⌘F 聚焦搜索，⌥⌘R 刷新。顶栏的快捷键说明按“全局 / 右侧视图 / 显示开关 / 搜索与列表”分组列出全部快捷键。

全局后退 / 前进（2026-11-09）：⌘[ / ⌘]、顶栏页面切换左侧的 ← → 按钮和鼠标侧键，在记录过的位置之间来回，按钮悬停时写明去向（如“后退到 提交 92aa8c23”）。只有跳转算一步：跨页面跳转与页面切换、文件页打开另一个文件、打开或关闭某次修改、逐行追溯跳转、打开目录历史；在列表里移动选择、滚动、切换浏览范围和刷新不算。回到某一步时重新读取那个位置，不还原像素级的滚动。提交页处于“从搜索定位到历史”时，⌘[ 先用于返回搜索结果（这也是一次后退）；从搜索结果定位到历史用 ⌘L。每个仓库最多记 50 步，换仓库时清空。

浏览范围紧跟在页面切换之后，只影响提交页和文件页；在工作区页变淡，但仍可打开。改浏览范围不会把工作区换成别的目录。

当前页面有可用的查找或筛选时，顶栏显示带范围前缀的搜索框，⌘F 聚焦它。统计页、文件页未选中可查找内容等情况下，隐藏搜索框、窄窗口的搜索按钮和对应快捷键提示。⌘K 打开独立的快速跳转面板。
- 提交页：“提交消息”，即现有的元数据搜索与筛选。
- 文件页（选中文件）：“当前文件”（文件名在面包屑里，长文件名放在这里会挤掉输入框），在已加载的内容里查找，不发新查询。没超过行数上限的文件整个加载，查找覆盖全文；被截断的文件，计数和“没有找到”都写明只查了前 N 行，不让人误以为整个文件里没有。
- 文件页（选中目录）：“目录历史”，搜索提交消息，路径条件固定为这个目录。文件的历史在历史列顶部的筛选框里按提交消息筛选。前缀保持简短，窄窗口下输入框的提示文字仍能完整显示。
- 工作区页：“改动的文件”，按路径过滤左栏。

顶栏位置固定，窗口变窄时按顺序缩减：先缩搜索框，再收近期活动的数字和刷新的文字；更窄时页面切换只留图标和角标，搜索收成按钮（点它或按 ⌘F 展开），快捷键说明收进“⋯”；最后截断仓库名和分支名。仓库、页面切换、浏览范围、“有 N 处更新”和刷新始终可见，悬停说明给出完整文字。

### 工作区状态与改动

顶栏「工作区」切换项用角标表示状态：有改动时显示文件数，有冲突时显示“冲突 N”，完整读取且没有改动时显示绿点。首次读取时不显示数字；读取后文件又变化时保留上次的数字并改为空心角标；结果不完整时数字是下限（如“2000+”）；读取失败显示“?”。悬停说明给出目录、实际分支和读取时间，读屏文字为“工作区干净”或“工作区：有 N 个文件改动”。浏览范围不是工作区所在分支时，切换项写出工作区的分支（如“工作区 · main”），detached 时写短 OID；两者一致时不写。bare 仓库没有工作区，这一项置灰不可点。

工作区页左栏按已暂存、未暂存、未跟踪和冲突分组列出文件，右侧显示所选文件在这一组里的 diff 或内容。已暂存对比 HEAD 与 index，未暂存对比 index 与工作区；同一文件可同时有两类改动，总文件数按路径去重，右侧注明另一组也有改动。未跟踪文件计入改动，忽略文件默认不列出。冲突仅展示状态和带冲突标记的内容，未跟踪文件提供有界内容预览，二进制 / 大文件明确说明。

工作区状态对应本窗口实际打开的目录和实际分支，与当前浏览的分支范围区分。Agent 修改文件后可自动复核这部分状态，并保留手动刷新；标明观察时间，不改变固定历史快照、提交选择或滚动位置。仅完整读取并确认无改动时才算“干净”；初次读取、失败、过期或不完整状态要明确表达。

### 文件二级页面

提交列表继续作为默认主界面，文件页是并列的第二个页面：从左到右是目录树、可开关的历史列和文件内容（2026-11-09 按试用反馈修订，取代「内容 / 历史」两个标签页）。目录树展示选定分支或提交的已提交快照，不含工作区改动，查看其他分支无需切换工作区；全部分支没有唯一目录树，需要先选一个树的版本。文件历史默认查询该版本的可达历史，不混入实时工作区内容。

提交详情的文件行可“在文件页打开”这个文件，显示目录树版本里的内容（这次提交删除的文件改为打开它的历史并选中这次修改；之后被改名或删除、当前版本里已没有的文件，改为在它的历史里选中这次提交并显示“这一版的文件”，目录树版本不变，“这一版的文件”标题注明“目录树版本里已没有这个文件”）；工作区页所选文件的“在文件页打开”打开这个文件在 HEAD 里的版本，也就是这些改动的出发点（浏览范围是别的分支时，目录树版本切到 HEAD，版本选择器写明；暂存区里改名的用改名前的路径；未跟踪和新增、还没提交过的文件没有这个按钮）；文件历史可“在提交页查看”这个提交，往返保留选择、筛选和阅读位置。跨页面跳转后，顶栏的后退按钮展开成“← app.ts”“← 提交 92aa8c23”“← 工作区”，说明从哪里来、点它就回去；之后在这个页面上又走了几步，← 恢复为后退一步，旁边保留“↩ 提交 92aa8c23”直接回到来源。回到来源页面或再跳转一次后提示消失。首版复用现有字面路径查询，明确不跨重命名追溯；跨重命名历史和任意双版本比较继续作为后续候选。

## 基础操作（已确认规划，待实现）

### 划分原则

App 只做**一步完成、不会产生冲突、不会丢数据**的操作。操作可能进入中间状态（冲突、合并或 rebase 进行中）时，App 不执行，仓库保持原样，由用户交给 Agent 或在终端处理。App 负责发现问题并说清楚，不负责解决。

所有操作只由用户显式触发，不自动 fetch，不在后台定时执行。浏览分支仍只改变查看范围，不 checkout；切换分支是单独的显式操作。

### 第一批操作

| 操作 | 行为 | 做不到时 |
| --- | --- | --- |
| Fetch | 更新远端跟踪引用，不碰工作区和本地分支；可选同时清理远端已删除的分支。完成后自动刷新到新快照，保留所选提交和滚动位置 | 认证或网络失败时显示 Git 的原始错误，提供“重试”“在终端打开”和“交给 Agent” |
| 更新当前分支 | 先 Fetch（当前实现获取所有远端，包含该分支上游），再只做快进；工作区文件随之更新 | 已分叉、没有上游、或快进会覆盖未提交改动时不执行快进，说明原因；与上游新增文件同名的未跟踪文件另见「同名未跟踪文件」 |
| 快进其他本地分支 | 不 checkout，把本地分支快进到它的上游 | 已分叉、没有上游、或该分支被某个 worktree 检出时不执行 |
| 切换分支 | 把本窗口工作区切到所选本地分支；选远端分支时新建同名的跟踪分支再切换 | 会覆盖未提交改动、目标已被其他 worktree 检出、或有进行中的合并 / rebase 时不执行；不强切，不自动 stash |
| 新建分支 | 从所选提交或分支新建本地分支，可选是否随即切换 | 名称不合法或已存在时提示，不覆盖 |
| 复制与打开 | 复制分支名、提交消息；在终端、编辑器、Finder 中打开工作区；在远端网页打开提交或分支（仅识别常见托管地址） | 远端地址识别不了时不显示网页入口 |

“更新”在界面上是一个动作：领先 / 落后数来自本地已有引用，并写明上次 fetch 的时间；点“更新”才联网。

入口（2026-11-12 按设计画布确认，对照「CherryPeek 统计页」画布的“基础操作”一排）：

- 顶栏（2026-11-13 用户确认调整）：刷新左边为组合按钮，主按钮“更新 main”（按本窗口工作区实际检出的分支命名），先 Fetch 再只做快进；即使本地快照暂未发现落后也可点击。目标与浏览范围独立。下拉保留 Fetch 和“Fetch 并清理失效引用”，只获取远端信息。Fetch 期间显示“正在 Fetch”、已用时间和取消按钮。Fetch 完成后停止计时并刷新快照，快进阶段不可取消；detached HEAD、空分支和裸仓库禁用主按钮并说明原因，保留 Fetch。Fetch 成功但快进被拒绝时，明确说明“Fetch 已完成；本地分支和工作区未更新”。
- 页面切换的工作区项：当前分支落后上游时在分支名后显示落后数（如“工作区 · main ↓5”）。
- 仓库弹层「当前工作区」：分支一行写领先 / 落后数和“更新（快进 N 个提交）”；目录旁是在 Finder、终端、编辑器中打开；远端一行有“在网页打开”。
- 范围菜单：点分支行仍然只改变浏览范围，操作在行尾。能快进的显示“更新”；已分叉的显示分叉计数和“交给 Agent”；被其他 worktree 检出或没有上游的不显示按钮。悬停时出现“切换”、复制分支名和“⋯”菜单（切换、从这里新建分支、复制分支名、在远端网页打开）；远端分支的按钮是“切换（新建本地分支）”。
- 提交详情：标题旁的“⋯”菜单提供从这里新建分支、复制提交消息、在远端网页打开。
- 新建分支对话框：显示起点、分支名输入（不合法时就地提示并禁用确认）、“创建后切换到这个分支”。

### 做不到时交给 Agent

操作被拒绝时，提示包含三部分：

- **原因**，用事实表述。例如“本地 main 与 origin/main 已分叉：领先 2、落后 5”“这 3 个文件有未提交改动，切换会覆盖它们”。
- **未执行本地操作**的说明。检查在执行前完成；Git 自身的拒绝是最后一道保护。更新包含已完成的 Fetch 时，只保证没有继续快进，不把已更新的远端引用描述成“仓库未被改动”。
- **交给 Agent**：打开既有的交接对话框，prompt 里带上仓库路径、分支、两侧 OID、涉及的文件和用户想达成的目标；另提供“在终端打开”。模板见 [HANDOFF](HANDOFF.md)。App 不调用 Agent，只复制文本。

执行中途失败（例如快进时磁盘写入出错）时，显示 Git 的原始输出和当前实际状态，不自动回滚，也不重试。

### 同名未跟踪文件（P5-06）

起因：2026-11-13 更新 `ai-native-workspace` 被两处未跟踪路径挡住。只读核对后，上游新增的 19 个同名文件里 18 个与本地逐字节相同，1 个是本地旧稿。用户希望在这种情况下能自己决定如何处理旧稿。

更新当前分支遇到与上游新增文件同名的未跟踪文件时，逐个比较。被 Git 忽略的同名文件也适用，忽略目录里的其他文件继续保留。

- **内容相同**（内容与文件类型都和上游一致）：不算覆盖风险，不需要确认。更新后这些文件成为已跟踪文件，内容不变；更新详情显示数量。
- **内容不同**：仍然拒绝，拒绝提示逐个文件标出“未跟踪 · 与上游不同”和相对上游的增减行数。“交给 Agent”保持主按钮；当挡住更新的只有这类文件时，另提供“备份并更新”和“丢弃并更新…”。选择丢弃时，再次列出受影响的文件和数量，用户确认后才执行。快进成功后，备份选项将不同副本保存在应用数据目录，丢弃选项清除本次临时副本。完成提示只显示分支和处理数量，点击“详情”可看相同文件数及备份目录。
- 未跟踪目录按其中会被上游写入的文件逐个比较；目录里上游不涉及的文件不动。
- 以下情况维持原有拒绝，只能交给 Agent 或在终端处理：已跟踪文件的未提交改动（暂存或未暂存）、类型不一致（一边是文件、另一边是目录或子模块）、签出时可能转换文件内容（例如 Git LFS 或换行转换）、同名文件数量或体积超过比较上限、同时存在其他拒绝原因。
- 按整个文件选择，不提供逐块合并或编辑。确认之后到执行之前，只要涉及的文件有变化就不执行，重新给出当时的事实。
- 快进没有完成时，把让开的文件放回原处；放不回去时保留备份并在提示里写明备份目录。

已跟踪文件改动的处理、分叉同步与轻量三栏冲突点选见 [路线图](ROADMAP.md)「后续线路：审阅收口与三栏轻量合并」，待排期。

### 与只读浏览的关系

- 操作成功后，历史、搜索、统计和工作区状态统一刷新到新快照，等同于用户点了“刷新”。更新的 Fetch 步骤完成后先刷新远端快照，再检查和执行快进；快进被拒绝时保留已 Fetch 的快照，中途失败时重新读取实际状态，不回滚 Fetch。
- 操作进行中显示进度并可取消。取消 fetch 不会损坏仓库；切换和快进是本地的短操作，开始后不提供取消。
- 同一仓库同时只执行一个操作；操作期间浏览和搜索照常可用。
- 合入状态、“与 origin 一致”等判断仍只反映本地引用，fetch 之后才是新的远端状态。

### 审阅收口与推送（M7，2026-11-17 开放白名单）

围绕“不打开传统 IDE、对着 Agent 终端进行 Vibe Coding”的使用场景，在「基础操作」之外开放 M7 单步零冲突收口能力；依然坚守**不进入冲突中间态**边界，遇分叉、冲突或 hook 失败时保持仓库可预期原样，并提供「交给 Agent」交接：

| 操作 | 行为 | 做不到时 |
| --- | --- | --- |
| 非强制 Push / 发布分支 | 把本地领先的提交推到上游远端；无上游的新分支可选择远端首次推送并设 `--set-upstream`。严禁 `--force`；推送进行中可取消，成功后刷新并重读同步状态 | 本地已分叉或远端非快进拒绝（`RemoteRejected`）时绝不强推，保持本地与远端原样，提供“交给 Agent…”和 Fetch；网络/认证失败提供“重试”“在终端打开”“交给 Agent” |
| 删除已合入本地分支 | 仅对祖先已合入基准（`merged`）、非基准、非当前 HEAD 且未被任何 worktree 检出的本地分支提供直接删除（`update-ref -d` 并清理分支配置） | 仅补丁等价（`patchEquivalent`）或被 worktree 检出的分支不直接删，保留原有的“交给 Agent 清理” |
| 本地分支快进合入目标分支 | 将本地特性分支快进合入目标本地分支（如 `main`），确认弹窗展示带入提交列表，可选合入后是否切到目标分支 | 目标被其他 worktree 检出、会覆盖未提交改动或两侧已分叉时拒绝，给出原因、两侧独有提交并引导“交给 Agent…” |
| 工作区审阅交接 | 「工作区」页提供全局“交给 Agent ▾”（审阅未提交改动 / 让 Agent 整理并提交）及单文件详情“交给 Agent…” | 只读复制结构化 prompt，不直接调用外部 Agent |
| 工作区暂存 / 丢弃 / 提交 | 支持单文件及全量暂存 / 取消暂存（覆盖初始空仓与重命名）、二次确认丢弃单文件未暂存修改或未跟踪文件、自动载入未提交草稿消息（`MERGE_MSG` / `SQUASH_MSG` / 与 `HEAD` 不同的 `COMMIT_EDITMSG`）并审阅编辑后 Commit（`--cleanup=whitespace` 保留 `#` 开头正文） | 有冲突未解决、路径越界或状态已变化时拒绝；`pre-commit` / `commit-msg` hook 失败时完整保留暂存区和输入框消息，展示原始报错并可一键“交给 Agent…”修复 |

M7 入口分布：
- 顶栏：保留既有「更新 {分支}」组合按钮不变；当前工作区分支领先上游（`↑N` 且不落后）或无上游且有远端时，在旁显示「推送 ↑N / 发布分支」按钮（推送中显示已用时间与取消），同时在「更新 ▾」下拉菜单、仓库弹层「分支」行、范围菜单分支行与 `⌘K` 提供对应入口。
- 范围菜单：分支行 `⋯` 提供「快进合入 {目标}…」「推送 / 发布分支」；满足祖先已合入且未检出的本地分支行提供「删除」（`⋯` 仍保留「交给 Agent 清理…」）。
- 工作区页（`⌘3`）：左栏头部设「交给 Agent ▾」与「全部暂存」，已暂存标题行设「全部取消暂存」，文件行与右侧详情头部设「暂存」「取消暂存」「丢弃…」「交给 Agent…」，左栏底部为 Commit Message 审阅提交区（遵守输入法组词，`⌘Enter` / `Ctrl+Enter` 提交）。

### 分叉同步与三栏轻量合并（M8，2026-11-18 开放白名单）

针对“更新当前分支、推送或快进合入目标分支时遇到分叉、且工作区没有已跟踪未提交改动”的场景，提供**零中间态**只读预演与轻量次选（“交给 Agent”仍保持默认主操作）：

| 场景 | 行为 | 拒绝 / 转交条件 |
| --- | --- | --- |
| 零中间态三方预演（`previewMerge`） | 在独立临时对象目录运行 `git merge-tree --write-tree -z`，不改被查看仓库 `.git/objects`、`.git/index`、引用或工作区文件 | 目标被其他 worktree 检出、已有进行中操作（`merge`/`rebase` 等）、工作区有已跟踪脏改动（`staged`/`unstaged`）、无共同祖先、多共同祖先（criss-cross）、引用已移动时拦截 |
| 无冲突分叉一键同步 | 两侧提交可干净自动合并时，提供 **合并同步（生成双父合并提交）**，当本地仅领先 1 个单父普通提交且线性变基亦无冲突时可选 **变基同步（线性重放该提交，保留原 Author 信息）**；可勾选同步后立即执行非强制推送 | 存在碰撞工作区未跟踪/忽略文件、需多步交互式 `rebase` 时拒绝并交回 Agent |
| 普通文本冲突三栏双边箭头视图 | 仅含普通文本冲突（`CONFLICT (contents)` / `add/add`，且文件数 ≤ 10、单文件 ≤ 128 KiB、总量 ≤ 512 KiB）时进入全宽左-中-右三栏视图：无冲突差异块自动合入中栏，冲突块初始保持共同祖先基底（不写 `<<<<<<<` 标记），装订线提供 `»` / `«` 推入、按点击顺序双侧拼接、`×` 忽略、中栏就地微调、单块 `↺` 重置与上下冲突跳转 | `Esc` 或「交给 Agent」直接退出零残留；重命名/删改/目录文件/二进制/非 UTF-8/子模块或超限文件均判为不支持，引导「交给 Agent…」 |
| 原子落盘与推送 | 全部冲突块清零且提交说明非空时，先写对象并原子构建树与提交，再一步更新分支与工作区；可选紧接非强制推送 | 更新工作区前复核引用与未跟踪碰撞，任意一步不满足保持原样不变 |

### 不做

`reset`、`stash`、多步或交互式 `rebase`、`cherry-pick`、`revert`、`force push`、脏已跟踪工作区按块合并、接手进行中的合并 / 变基、结构性冲突自动解算（重命名 / 删改 / 目录文件 / 二进制 / 子模块 / 多共同祖先）、自动 fetch 继续不做，统一通过“交给 Agent”完成。

## 统计页（已确认规划，未实现）

2026-11-12 用户确认把统计做深：从“多少提交、哪天、谁”扩展到“改了哪里、改了多少、有什么值得注意”。任务见 [实施计划](PLAN.md) 的 M6。本节是规划；锁文件排除和测试 / 文档的识别规则已于同日确认。按 `Co-Authored-By` 统计 AI 协作占比暂不做，trailer 仍只用于展示。

### 入口与范围

统计从顶栏弹层改为第四个页面「统计」（⌘4），顶栏的活动小柱保留，点击进入统计页。统计页沿用当前浏览范围、固定快照和提交页的全部筛选（含新增批次拓扑范围 `excludeTips`）；页内另有时间范围（1 小时 / 3 小时 / 6 小时 / 12 小时 / 今天 / 7 天 / 30 天 / 90 天 / 自定义，支持按天与精确到时分）和粒度（10 分钟 / 小时 / 天 / 周 / 月），并支持一键切换“只看上次更新 / 自上次查看新增批次”。粒度默认随范围自动选择，可以手动改；对当前范围太粗的档位不可选。在按时间的图上拖动框选一段，可以把范围放大到那一段，或在提交页查看那一段的提交（2026-11-12 用户要求更细的时间粒度）。界面对照设计画布「CherryPeek 统计页」（未公开，示例数据）。每个图表上的元素都可以点：点某天、某人、某个目录或文件，回到提交页并加上对应筛选。

索引未覆盖完整时，每个数字标“部分”，写明已覆盖的提交数；不显示未知总量的百分比。

### 第一层：活动（用现有元数据索引）

| 统计 | 内容 |
| --- | --- |
| 周期对比 | 提交数、活跃天数、活跃作者数，与上一个等长周期比较，写出差值 |
| 时段分布 | 星期 × 小时热力图，按所选时间字段和本地时区 |
| 提交节奏 | 最长连续有提交的天数、最长间隔、单日最多提交数及日期 |
| 提交类型 | 按标题前缀分组（`feat`、`fix`、`docs` 等 Conventional Commits 写法），不符合的归“其他”；merge 提交单列 |
| 撤销与修正 | 标题以 `Revert` 开头的提交数；`fixup!` / `squash!` 提交数 |
| 分支活跃度 | 每个本地分支在周期内的提交数、最近一次提交时间；超过 30 天没有提交的列为“不活跃” |
| 连续提交时段 | 相邻提交间隔不超过 10 分钟的归为一段，列出起止时间、时长、提交数、作者、增删行数和涉及的目录；点一段在提交页查看。范围在一天以内时显示（增删行数和目录依赖第二层的数据，未就绪时不显示这两项） |

### 第二层：改动量（需要在索引里记录每个提交改动的文件）

| 统计 | 内容 |
| --- | --- |
| 改动量 | 按天、按作者的增加行、删除行、改动文件数；与提交数并排显示 |
| 热点 | 改动最集中的目录和文件，可按提交次数或行数排序；目录可逐级下钻 |
| 作者 × 目录 | 每个作者的改动落在哪些顶层目录 |
| 提交粒度 | 提交大小的分布（按改动行数分档），列出周期内最大的若干个提交 |
| 文件类型 | 按扩展名统计改动行数；按路径规则分出测试和文档 |
| 净增长 | 增加减删除的累计曲线 |

口径：

- 行数相对第一父提交计算；merge 提交不计入行数和文件数，避免把合入的改动算两次，根提交与空树比较。
- 统计行数时启用整文件重命名检测，移动文件不算成整份删除加新增。这与路径历史的字面匹配不同，统计页上注明。
- 二进制文件只计文件数，不计行数。
- 生成文件和锁文件会主导行数。默认从行数中排除一组常见锁文件（如 `pnpm-lock.yaml`、`Cargo.lock`、`package-lock.json`），列表可在统计页按仓库修改，被排除的行数单独显示。
- 测试与文档按路径约定识别：路径中有 `test`、`tests`、`__tests__`、`spec` 目录，或文件名含 `.test.`、`.spec.`、`_test.` 的算测试；`.md` 文件和 `docs/` 下的文件算文档；其余算代码。规则写在统计页的说明里，识别不了的仓库结果会偏，不据此下结论。

### 第三层：值得注意的地方（由第二层的数据推出）

| 统计 | 内容 |
| --- | --- |
| 反复修改的文件 | 周期内被多个提交改动的文件，按次数排序，显示涉及的作者数；这是返工或热点的信号，不下结论 |
| 常一起改的文件 | 在同一个提交里共同出现次数最多的文件对；只统计改动不超过 50 个文件的提交，避免批量改动淹没结果 |
| 单人维护的目录 | 周期内只有一个作者改过、且改动不少的目录 |
| 代码与测试 | 改了代码但没改任何测试文件的提交占比（按上面的测试路径规则） |

这一层只陈述观察到的事实并给出可点开的提交列表，不打分、不给“健康度”之类的结论。

### 第四层：演化（按需分析）

2026-11-12 用户确认：这一层回答“现在的代码是什么时候、由谁写的，写下的代码留下来多少”。它要对文件逐行追溯，成本高，所以不随索引自动计算，只在用户选定范围后点“开始分析”时运行。

| 统计 | 内容 |
| --- | --- |
| 代码年龄 | 所选范围内现存的行，按最后修改时间分档（近 7 天、近 30 天、近 90 天、近一年、更早） |
| 当前归属 | 现存的行按最后修改它的作者分布；与“谁提交得多”分开显示 |
| 代码存活 | 所选时间段内新增的行，到当前版本还剩多少；按作者和按周列出，可点开对应提交 |

用法与口径：

- 范围是一个目录或一组文件，加一个可选的时间段；版本是当前浏览快照的尖端（“全部分支”范围需要先选一个分支）。页面先显示将分析的文件数和估计规模，用户确认后才开始。
- 分析逐个文件进行，显示已完成的文件数，可以随时取消；已完成的文件结果保留并缓存，下次分析同一版本时直接使用。
- 每次分析的文件数有上限；超过逐行追溯单文件上限（1 MB 或 20,000 行）的文件、二进制文件和排除列表中的文件跳过，并列出跳过了哪些。结果写明覆盖了多少文件和多少行，不把部分结果当成全部。
- 存活率 = 时间段内各提交在当前版本中仍被追溯到的行数 ÷ 这些提交新增的行数（第二层的数据）。追溯只跟随整文件改名，所以在文件之间移动或复制的代码算作新写的，原处算作被删；仅改空白的行也算被改。页面上注明这是近似值。
- 这一层同样只陈述结果，不评价作者或提交的好坏。

### 不做

按 trailer 统计 AI 协作占比、推断某个身份是不是 Agent、需要解析代码的语义分析（函数级历史、复杂度趋势、依赖与接口变动）、跨仓库汇总。Git 里没有的信息也不估算：工作时长、评审与 CI 结果、被改写掉的历史。

## 第一版边界与后续假设

已发布的第一版只负责展示，具体的 Git 操作通过“交给 Agent”复制 prompt，由用户交给外部 Agent 完成；App 不直接调用 Agent。2026-11-12 起按「基础操作」一节加入白名单内的操作，2026-11-17 起按「审阅收口与推送（M7）」开放审阅收口与非强制推送白名单，2026-11-18 起按「分叉同步与三栏轻量合并（M8）」开放零中间态分叉同步与普通文本冲突三栏轻量合并；白名单之外（重型结构化冲突解决、多步变基、完整 review 工作流、PR / 账号集成、云同步、AI 总结、Agent 身份推断和自动远程更新）仍不提供或不做。远端跟踪分支展示的是本地已有引用，注明更新时间。

按代码增删内容搜索、跨重命名历史、跨仓库活动、多 worktree 聚合视图和包含关系的进一步分析放到后续阶段。Linux、正式命名和商业模式不阻塞首个 macOS 闭环；Windows 是计划中的第二验收平台。

浅克隆、缺失对象与 partial clone 必须显示数据边界；MVP 不自动补拉对象。子模块作为独立仓库打开，父仓库详情只显示 gitlink 变化。bare 仓库支持在 M0 验证，若暂不支持，明确提示而非误报为空仓库。
