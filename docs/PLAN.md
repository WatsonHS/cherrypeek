- [ ] **P1-02 历史查询与游标。** 固定 tip 快照，实现流式分页、有界缓存、游标失效与手动刷新接口；记录深页重读成本。依赖 P1-01。完成条件：固定 fixture 完整遍历无重复 / 遗漏；同时间戳和 merge 历史次序稳定，外部连续提交不改变当前遍历，主动刷新后不会拼接两个快照。
- [ ] **P1-03 虚拟历史列表。** 显示摘要、Author（身份头像按 PRODUCT 配色规则）、时间、OID、引用标签，标出上次查看后新增的提交（连续时显示“上次看到这里”分隔线），支持键盘选择、复制、错误重试和有限预取。依赖 P1-02。完成条件：前端保留行数有界，快速切换范围不闪回旧数据；新增标记与独立 `git rev-list <当前 tips> --not <上次 tips>` 一致，首次打开不标记；10 万提交滚动记录满足已冻结预算或留下待修复测量。
- [ ] **P1-04 分支与 worktree 导航。** 范围选择器列出 HEAD 可达历史、全部分支、worktree（主或 linked、HEAD 指向、路径）、本地分支、远端跟踪分支、标签与 detached HEAD；顶部显示本窗口 worktree 入口；分支与 worktree 点击仅切换范围，提供手动刷新入口；本地分支显示被哪个 worktree 检出，并通过 `refMergeStatus` 显示相对默认分支的合入状态（第一版只显示“已合入”）。依赖 P1-03。完成条件：浏览前后 worktree、index、HEAD、refs 均不变，界面分清当前工作区与查看范围；基准按 origin/HEAD → origin/main → origin/master 解析，没有远端跟踪分支时退回本地 main → master，都不存在时不显示；可达判断与独立 `git merge-base --is-ancestor` 一致；不可达时不显示标签，不给“未合入”结论（squash / rebase 识别见 P4-08）；刷新尽量保持所选 OID 与滚动锚点，引用或锚点已不存在时明确提示，不暗中替换选择。
- [ ] **P1-05 元数据索引。** 引入 SQLite schema、事务、版本与可重建缓存；后台可暂停 / 取消，记录绑定快照的 coverage 和磁盘配额。依赖 P1-02，不依赖图布局或 diff。完成条件：建索引中途退出后重启可恢复；索引缺失 / 损坏不阻止基础浏览，达到配额时不会误报完整；外部新快照不使当前固定快照的索引任务反复重启。
- [ ] **P1-06 元数据搜索。** 消息搜索框配合 OID / Author / Committer / 日期 / 分支筛选；字段间 AND、同一身份字段多选 OR，提供文本大小写开关并确定其初始状态及 Unicode 匹配规则；筛选弹层包括“添加条件”菜单、Author / Committer 身份多选、Hash 输入、提交时间预设与自定义起止日期（包含起止两天）。依赖 P1-03、P1-04、P1-05。完成条件：中文短词、标点、大小写、标题与正文、hash 歧义及身份区别验证通过，普通消息框不自动切换为 hash 查询，索引前后完整结果一致；部分结果按时间与 OID 自动合并、去重，保持选中项与视口锚点，跨结果版本分页无重复遗漏且前端行数有界。此阶段可选择搜索结果摘要；图形定位与返回在 P2-04 接入。

**阶段验收：** 从未建索引的仓库进入可交互历史 → 输入消息 → 组合身份 / 日期 / hash 筛选 → 选择真实命中摘要；范围切换、深页、取消、手动刷新和部分结果合并可用。记录真实仓库搜索试用证据；图、diff、路径搜索、活动统计与自动更新通知尚未齐全。性能未达标时记录原因，不将 M1 验收等同于最终性能验收。

## M2：分支图与提交详情

- [ ] **P2-01 图布局与跨页检查点。** Rust 生成 lane / edge 信息，前端按可见区域绘制；图区固定最多显示 6 条线，超出的线不画，在图区右侧显示“+n”（拖宽、展开与悬停高亮见 P4-05）。依赖 P1-02。完成条件：线性、merge、octopus、长边、浅克隆边界、跨页返回的布局验证通过；线条与表格缩放 / 行高一致；隐藏的线不改变 lane 分配和颜色，10 万提交、约 1,000 refs 场景下滚动仍满足预算或留下测量。
- [ ] **P2-02 提交详情与文件列表。** 详情「概览」按 OID 加载完整消息与解析出的 trailer、双身份、双时间、父提交、引用与 worktree 位置和改动概览（数量、类型、按目录汇总），所选提交受未载入的更新影响时在详情头部提示一行（用时间表述）；merge 提交的概览列出带入的提交及其作者分布；“包含它的分支”点击后经 `branchesContaining` 计算；「文件改动」标签页列出文件，以选定父提交为基准。依赖 P1-03、P1-04。完成条件：root、merge、重命名、删除、非 ASCII / 含换行路径、gitlink 正确；包含分支与独立 `git branch --contains` / `git branch -r --contains` 一致；trailer 与 `git interpret-trailers --parse` 一致；带入的提交与独立 `git rev-list <第 N 父> --not <第一父>` 一致，octopus 按父提交分组；切换选中项不被旧响应覆盖。
- [ ] **P2-03 按需只读 diff。** 仅请求选中文件；支持父提交切换、二进制提示、大小限制和截断说明。依赖 P2-02。完成条件：大 patch 不冻结窗口；无隐式 textconv / 外部 diff / 网络请求；字节异常不导致协议损坏。
- [ ] **P2-04 历史定位与交互。** 将 M1 搜索接入 locateCommit、返回位置锚点和详情面板，定位后显示说明横幅与“返回 N 个结果”；加入快捷键说明（⌘K 命令面板见 P4-07，窄窗口布局见 P4-06）；验证中文输入、键盘、缩放和深浅主题。依赖 P1-06、P2-01、P2-03。完成条件：定位时暂时移除全部字段筛选，在原范围和快照显示图形上下文；深历史定位可取消，查询范围外的 OID 有明确提示，返回后保留原查询、选择和滚动锚点；输入法组词期间快捷键不触发。M3 加入路径筛选后复验相同返回行为。

**阶段验收：** 元数据搜索 → 在历史中定位 → 返回搜索；浏览图 → 选择 merge commit → 切换父提交 → 选择文件看 diff。完整流程不修改被查看仓库。

## M3：路径历史、统计与外部更新

- [ ] **P3-01 路径历史。** 文件与目录的字面路径过滤，支持与元数据条件组合；路径条件弹层提供当前状态下的路径补全和“包含子目录”开关；merge 按任一父提交变化匹配，并标注命中父提交。依赖 P1-06、P2-03。完成条件：含空格 / 特殊字符路径、删除、merge 第二父提交的变化测试正确；说明不跨重命名追溯；路径结果沿用部分结果自动合并和锚点保持规则。
- [ ] **P3-02 活动统计。** 基于当前浏览快照与完整查询条件计算去重提交数、逐日分布和按 Author 分布，支持时间口径与本地时区；点某天或某个身份即加入对应筛选。依赖 P3-01。完成条件：多分支共享提交、乱序时间、Author / Committer 差异、日界 / 夏令时测试通过；身份分布按原始姓名与邮箱分组，与独立计算一致；全部有效筛选与历史 / 搜索一致，索引未完成和耗时路径查询不显示假精确总量。
- [ ] **P3-03 外部变化通知与刷新。** 文件事件合并、聚焦复核和可见窗口兜底检查只推进最新已观察 generation，提示“有 N 处更新”；点开经 `diffRefSnapshots` 按引用列出快进、改写、新建、删除；点击刷新再切换当前浏览快照。依赖 P1-04、P1-05、P1-06。完成条件：快进 / 改写分类与独立 `git merge-base --is-ancestor <旧> <新>` 一致，被替换数与 `git rev-list <旧> --not <新>` 一致；连续提交期间固定快照的搜索能够完成，结果不混入新快照；amend、rebase、分支删除、worktree 更新有正确提示；刷新后保持有效的选择与锚点，对失效范围明确提示，新快照索引可达性不残留旧结果。
- [ ] **P3-05 交给 Agent。** 详情头部、分支行更多菜单、merge 概览与相关状态卡片提供入口；经 `getHandoffFacts` 生成同步到 origin/main、审阅提交、解释 merge 带入的改动、清理已合入的分支与 worktree、自定义五类 prompt，可编辑预览后经 `copyText` 一键复制。依赖 P1-04、P2-02、P3-03。完成条件：复制动作只写剪贴板，不启动进程；事实查询可调用只读 Git，不执行 Git 写操作；prompt 中的观察时间、OID、领先 / 落后数和两侧改动文件与独立 Git 命令一致；含伪指令或伪造分隔标记的提交标题、分支名和路径只出现在参考数据段内，正文只使用可解析的编号引用；区分浏览分支与操作 worktree，覆盖多条 prunable 记录、octopus、空仓库与无基准；模板、变量与防注入规则以 [HANDOFF](HANDOFF.md) 为准；清理场景只在已合入或内容已在 origin/main 时可选；输入法组词期间不触发复制。
- [ ] **P3-04 MVP 主路径验收。** 串联打开 → 统计 → 筛选 → 路径历史 → 定位 → diff → 外部变化提示 → 点击刷新 → 交给 Agent 并看到其改动带来的更新提示。依赖 P2-04、P3-01 至 P3-03、P3-05。完成条件：核心 fixture 与真实仓库通过；验证各数据区统一绑定快照、部分结果排序与锚点稳定，保存 `docs/validation/m3-mvp.md` 和未解决问题。

**阶段验收：** 能完成 PRODUCT 中第一版的完整路径；M3 交付功能齐全的只读 MVP，M4 继续处理长期稳定性与发行。

以下体验增强在 MVP 之后进行，不阻塞 M3 验收：

- [ ] **P4-05 分支图交互增强。** 图宽可拖（默认 4 条线、最多 12 条），超出的线收起成可点击展开的“+n”，悬停或选中提交时突出所在线、淡化其余线。依赖 P2-01。完成条件：拖宽、展开与收起不改变 lane 分配和颜色；约 1,000 refs 场景下滚动仍满足预算或留下测量。
- [ ] **P4-06 窄窗口布局。** 窗口宽度不足 1100px 时只保留列表，详情以右侧抽屉覆盖，Esc 关闭；搜索收成图标，worktree 入口与更新提示缩短。依赖 P2-04。完成条件：抽屉可用键盘打开、切换上一个 / 下一个和关闭；宽窄切换时保持所选 OID 与滚动锚点。
- [ ] **P4-07 ⌘K 命令面板。** 跳转到提交、分支、worktree 或执行命令，结果分组并显示快捷键。依赖 P2-04、P3-05。完成条件：输入法组词期间不触发；命令只改变查看状态或复制文本，不执行 Git 写操作。
- [ ] **P4-08 合入状态的补丁比对。** 可达判断不成立时，按 PRODUCT 口径只读比对补丁，显示“内容已在 origin/main”。依赖 P1-04。完成条件：与独立 `git cherry` / `git patch-id` 一致，fixture 覆盖普通 merge、squash、rebase、cherry-pick 以及合并时改过内容的 squash；比对超限或未完成时不给出否定结论；不使用会写仓库对象的命令。
