# P4-01：快速滚动与时间拖动

日期：2026-11-09。状态：本批实现与定向测量完成，内存预算和完整 P4-01 验收未完成。保留上一批尚未提交的内存优化。

## 问题与本批目标

滑轨已有一个在途请求加一个最新目标的合并调度，主要等待来自 Rust 每次日期定位重新扫描全部时间戳，以及深页恢复时重新启动 Git 并跳过前缀。滚动预取目前只提前一个视口，高速滚动容易先到达已加载内容的边界。

1. `history.rs`：为当前固定快照建立有总大小上限的日期与拓扑位置缓存。日期查找使用时间索引，图布局从原始有效父关系和既有检查点恢复，不能使用可能顺序不同的元数据索引 ordinal。首次完整扫描结束前不把部分缓存当成完整日期答案；超过上限继续正确查询并回退原扫描。取消、刷新 / 换范围、shallow / grafts 变化沿用原有约束。
2. renderer 历史列表：按滚动速度增加同方向预取距离并设视口上限；程序化定位、方向改变和换会话不能放大速度估值。分页落地后仍靠近边缘时继续检查，保持行数预算、反向取消和 OID 锚点。
3. 保留滑轨一个在途与一个最新目标的调度，拖动期间不反复取消首次缓存构建。最后释放的位置必须完成定位，过期会话结果不能覆盖当前列表。
4. 首轮实测显示后端变快后，逐次 pointermove 会频繁替换 200 条记录，增加 renderer 分配。拖动预览按约 120 ms 合并到最新目标；首次按下与最终释放优先处理，刻度提示继续跟随指针逐帧更新。计时器随取消、换会话和卸载清理，不启动额外详情查询。

## 分工与验证

核心代理负责历史缓存与相关用例，桌面代理负责滚动预取，测量代理提供一个轻量真实窗口脚本；主代理集成并串行执行前后对比。测量使用同一十万提交 / 千引用仓库和完整索引 profile，比较首次 / 后续不同日期的 IPC 时间、实际快拖放手后的等待、高速滚动到边缘的等待及前后返回数据。只运行受影响用例，记录增加的缓存预算与实测占用，不以无界预读换速度，也不把小样本当发布 p95。

## 完成结果

当前 Query 保存至多 16 MiB 的紧凑日期 / 有效拓扑索引；缓存完成后用二分找日期、从布局检查点位置直接读取缓存。六对日期页面字段与图数据一致，首次定位 947.1 → 518.5 ms，后续五个不同日期中位数 903.3 → 37.9 ms。滑轨预览合并到约 120 ms，最终位置优先，松手到首次稳定样本 1457.9 → 105.3 ms。快速滚动会按速度提前预取，实窗维持 1800 条摘要 / 37 行 DOM 上限；本轮前后都未采到滚动边缘等待。

Rust 历史定向 14 项、自适应预取用例、TypeScript 与 release 构建通过。没有扩展验证矩阵。连续拖动后 RSS 单点仍从 668.7 升至 787.9 MiB，主要增量在 renderer；请求合并缓解了第一个候选的增量，但内存预算尚未解决。完整条件、失败测量与后续边界见[本批实测](../benchmarks/p4-01-fast-history-navigation.md)。
