# P4-01：连续导航的 renderer 分配

日期：2026-11-09。状态：本批实现与定向对比完成，P4-01 完整发布验收仍待完成；内存预算随后按用户要求放宽，见 [VALIDATION](../VALIDATION.md)。基于 `d69c22d`，保留同期 P4-09 接口和 UI 修改。

## 定位结果与代码范围

在独立 release 构建中完成原导航测量，再取 renderer 堆快照、采样三轮真实滑轨 / 滚动操作。堆快照可能触发 GC，诊断阶段的 RSS 不与正常使用内存混用。三轮前后存活历史提交 / 图对象都为 2600 个，DOM 节点回到 1476，监听器回到 394；没有观察到随轮次增加的页面或 DOM 泄漏，不据此保证长时运行无泄漏。

采样约 1010 MiB 分配中，最大的业务热点是关闭状态的 `ScopePicker`：父组件更新仍构造千条引用菜单的 JSX。另一个热点是 `refsByTarget` 逐条展开同一目标的数组，以及普通翻页重复复制 snapshot 引用。

本批仅修改：

1. `top-bar.tsx`：只在打开范围菜单时构造 `PopoverContent` 子树；保持原打开、关闭、导航和合入状态行为。
2. `commit-list.tsx`：构建本次引用索引时在新建 bucket 内追加，不为同一目标的每条引用复制整个数组。不增加全局缓存。
3. `repository-session.ts` / preload / main IPC：为现有 `readHistoryPage` 增加可选 `contentOnly`，只省略 main → renderer 响应里的 repository / refs。Rust → main 仍保留完整帧和现有校验，不扩大本批协议改造。
4. `repository-session-store.ts`：普通相邻页读取使用内容模式，补上请求开始时捕获的当前 snapshot 对象。保留过期响应守卫、相邻页校验、1800 条上限、刷新和首屏完整读取。

## 检查与停止条件

复用会话状态用例，检查内容页可拼接、引用身份保持以及取消 / 淘汰 / 刷新。独立构建前后使用同 UI、同 fixture、同 profile 与相同操作；检查菜单能打开并从外侧关闭、页面数据相同及窗口有界。只跑受影响状态测试、类型检查与一次前后测量。本批不强制 GC 美化常态内存、不顺带修改图检查点或首次扫描。

## 完成记录

会话状态 38 项与独立构建类型检查通过，真实 Electron 比较的六对日期页 / 拖动落点一致；范围菜单显示 1000 条引用并可点击外侧关闭；完整页与内容页字段一致。同期 P4-09 接线完成后，主工作区类型检查也通过。
