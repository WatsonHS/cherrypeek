# P5-06 当前工作区更新的同名文件处理

本次接续已经接好的更新按钮和拒绝弹窗。用户确认忽略文件与普通未跟踪文件使用同一套比较和备份规则。手动合并编辑器另见路线图。

1. 在 Rust 核心协议增加预检相同数、按文件的行数差异、确认摘要及完成回执。只在当前工作区的 `fastForward` 请求接受 `replaceUntracked` 或 `discardUntracked`。同步 schema、桌面协议类型和主进程入参校验。
2. 在 daemon 预检中，以 HEAD 到目标提交的实际新增路径为候选，交叉检查索引、工作树类型、可执行位和上游 blob。忽略目录只检查受此次更新影响的路径。相同项单独计数，只有完整且全可替换的阻塞集合才能签发摘要。摘要绑定原始路径、本地快照、上游对象和此次操作。保留 200 个文件和 64 MiB 的比较上限。
3. 执行时重新预检。已确认的文件集合或分支状态改变时返回当前阻塞信息。把待让开的本地文件安全保存在应用数据目录，再在同一工作区执行快进。Git 失败时恢复本地副本，恢复路径出现新文件时保留备份并提供位置。核实快进成功后只保留用户选择的备份，回执给出相同、备份及丢弃数。
4. 弹窗保留 Agent 主操作；仅有可替换同名文件时提供“备份并更新”和需再次确认清单的“丢弃并更新…”。覆盖受跟踪改动、路径类型冲突和分支分叉分别沿用对应阻塞和 Agent 交接。
5. 在临时 Git 仓库验证相同、不同、忽略目录、令牌失效、混合阻塞、备份及失败恢复。运行协议生成一致性、Rust、桌面测试及 Electron 更新流程。真实使用中的仓库只做预检。

## 验证范围

- 真实仓库使用已存在的本地上游引用，只调用 `checkOperation`。独立 Git 读取在预检前后核对 HEAD、上游 OID、索引文件摘要和包含忽略文件的 porcelain 状态摘要。
- 执行测试使用临时仓库及单独的应用数据目录。独立 Git 和文件系统核对快进目标、未跟踪文件、备份的原始字节与 Unix 权限。通过已有的独立 index 锁触发 Git 失败，通过挂起 Git 子进程并新建同名文件验证并发恢复。
- 桌面测试通过真实 Electron 窗口点击“更新 main”，查看拒绝弹窗中的 Agent 主按钮和备份选项，从详情读取备份目录并逐字节核对副本。另验证取消丢弃、确认丢弃、保留其他文件与早前备份，以及慢 Fetch 期间的计时和取消。
