# P4-01 常驻内存优化

日期：2026-11-08。首批查询优化已提交 `670a5e3`，本报告记录其后的内存修改；P4-01 完整验收仍未完成。

## 改动与取舍

历史的 `rev-list --topo-order --parents` 原来通过 16 行队列向 Rust 传输。首屏只消费少量行，队列满后 Git 阻塞，约 36 MiB 的遍历进程长期驻留。现在只有历史拓扑采用固定 64 KiB 块预读，队列有效载荷上限 16 MiB，另有生产者 / 消费者工作块和有界行缓冲。十万提交参考仓库的拓扑可以完整进入缓冲，Git 自然退出，后续页继续消费相同的字节流。其余 Git 流仍保持原来的 16 行队列。

这增加了 Rust 缓冲占用，收益按整树总量计算。超出上限的大仓库仍有背压，不能承诺所有仓库都能在首屏后释放 Git。没有增加磁盘缓存，也没有改成每页重启遍历。单行上限、未终止行、Git 失败、取消、超时、快照检查和关闭回收保持原有语义。

main 的三份协议校验器改为构建期生成的 Ajv standalone CJS。生产运行时保留完整校验及原错误文本，省去 Ajv 编译器与动态 schema 编译。`protocol:check` 同时检查 schema、类型和校验器产物。代价是生成源码约 746 KB，main bundle 从 530,481 增至 1,384,284 字节；实测主进程 RSS 和活跃 JS 堆下降，因此保留该改动。

## 同口径实测

沿用[首批报告](p4-01-interactive-performance.md)的 MacBookPro18,3 / 32 GiB / macOS 27.0.1 / Electron 45.2.3，以及同一个十万提交、千条引用宽图 fixture、完整索引 profile、1180×760 前台窗口。两轮均为 release Rust 和构建后的桌面资源，renderer 资源未改。每次重启应用，确认索引覆盖完整后采样 15 秒；每 500 ms 统计整个 Electron 子进程树的 RSS，包括 Git。

优化前采用上一批最终记录 `p4-01-after-warm-20261108.json`，其二进制与提交 `670a5e3` 一致。优化后记录为 `p4-01-memory-after-20261108.json`。

| 空闲 RSS 中位数 | 优化前 MiB | 优化后 MiB |
| --- | ---: | ---: |
| 整进程树 | 603.0 | 566.3 |
| main | 201.8 | 192.2 |
| renderer | 213.4 | 213.3 |
| GPU | 84.3 | 85.3 |
| utility | 47.9 | 47.8 |
| Rust | 16.8 | 24.9 |
| Git | 35.8 | 0.0 |

整树下降 **36.7 MiB（约 6.1%）**；Rust 增加约 8.1 MiB，Git 中位数降为零，main 减少约 9.6 MiB。各角色中位数并非同一时刻，不能直接相加当整树中位数。定时引用观察仍会短暂启动 Git，优化后 Git 采样峰值约 5.8 MiB。

相同串行查询阶段的整树采样峰值 **689.7 → 623.4 MiB**。main 活跃 JS 堆 **12.7 → 6.8 MiB**。峰值是 500 ms 间隔内的采样最大值，可能遗漏短命进程峰值。

查询仍成功：前后 24 对样本的参数、提交行摘要（含图布局）、命中数、页偏移与活动 / 分支摘要一致，仅排除随 session 改变的 `resultVersion`。首次日期定位到 offset 25,000 / 12,400 分别为 **916.6 / 890.5 → 872.3 / 823.2 ms**；此样本未见日期定位延迟退化。搜索为正常波动范围，例如消息命中三次中位数 181.0 → 193.9 ms，OID 为 1.3 → 1.5 ms；不据此宣称查询继续加速或 p95 达标。

## 边界与证据

**566.3 MiB 仍高于 500 MiB 预算。** 此次没有修改统计口径、关闭沙箱或强制 GC，也未完成一分钟空闲 CPU、30 分钟运行或完整发布性能矩阵。

定位阶段另外用 vmmap 观察旧版本：main / renderer 的物理 footprint 约 66.6 / 114.5 MiB，JS 活跃堆约 12 / 17 MiB，表明 RSS 包含较多共享映射；该诊断不替代整树 RSS 指标，也不作为优化后的物理 footprint 对照。
