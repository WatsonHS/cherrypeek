# 统计调度修复后的真实仓库测量

日期：2026-11-12。目标是统计不被普通读取取消、演化可暂停并保留结果；没有为本轮统计查询新设毫秒级性能门槛。以下是单机实测，不作为发布性能验收，也不证明所有仓库都能达到这些数值。

## 样本与方式

- 本机真实 Prisma 仓库 `/Users/huangsheng/Development/prisma`，固定 HEAD `6e5acbcd105b9bc3416c6fb62e262b877e1aae1f`，可达 **10140 个提交**，文件索引 **56120 条记录**。没有生成或修改该仓库的数据。
- 本地快照最新提交日期为 2023-11-27。为衡量有内容的区间，统一取 **2023-11-28 00:00 Asia/Shanghai** 为排他终点，向前 30 / 90 / 730 天；这不是 2026-11-12 当天的活跃度。选 Committer 时间、按日分桶、HEAD 范围、空查询与默认排除列表。各区间实际有 140 / 449 / 2709 个提交。
- Apple M1 Pro，10 个逻辑 CPU，32 GiB，MacBookPro18,3，macOS 27.0.1；Git 2.54.0 (Apple Git-157)，Node 26.0.0。使用本轮 `cargo build --release --locked -p commitscope-daemon`，binary SHA-256 见[精简 JSON](stats-scheduling-data.json)。macOS 统计线程使用 utility QoS；stderr 为空，无优先级设置失败日志。
- 新缓存位于仓库外 `/tmp/commitscope-stats-prisma-cache-20261112`。先等元数据及文件索引完成：`coverage={processed:10140,complete:true}`、`state=complete`，无错误。首次索引等待 **290.00 s**，报告磁盘占用 **31.57 MiB**；这些不计入下面的统计耗时。索引期间可有其他验证工作，统计计时阶段本轮测试和构建已结束，主机仍非独占。
- 通过 JSON Lines 直接访问真实 daemon，计时从发出请求到收到终态，含传输和 JSON 解析，不含 Electron / renderer / 绘制。九个统计请求按 30 天、90 天、2 年，每组依次活动、改动、关注项执行，各测一次，不退避重试、不加测试等待点；全部成功，结果 coverage 均完整。
- 起初尝试 28626 提交的 `ai-native-workspace`，文件索引补建较慢，在索引未完整时停止；确认 daemon 退出，未使用其部分覆盖结果冒充性能数据。最终表格只来自上述 Prisma 仓库。

## 统计运行期间的历史读取

先预热固定快照的 200 条首屏历史页。每组先读空闲历史页，再启动 90 天 `getChangeStats`，等待 5 ms 后读同一历史页。客户端断言历史发出时和完成时统计都仍在执行，随后等待统计正常终态；五次统计结果 SHA-256 均与无干扰的 90 天基线相同，十次历史结果也完全一致。

| 对照组 | 空闲时 `readHistoryPage` | 统计运行期间 `readHistoryPage` |
| --- | ---: | ---: |
| 1 | 4.314 ms | 4.533 ms |
| 2 | 4.334 ms | 4.478 ms |
| 3 | 4.414 ms | 4.510 ms |
| 4 | 4.499 ms | 4.464 ms |
| 5 | 4.421 ms | 4.413 ms |
| 中位数 | **4.414 ms** | **4.478 ms** |

本样本启用低优先级统计后，并发历史热页的中位数增加 **0.064 ms（约 1.4%）**；绝对差值很小。这里只能说明该样本下没有观察到明显干扰，不能外推冷页、深页、CPU 饱和、慢盘或多仓库情形。没有执行普通优先级统计的 A/B 对照，不能把差值解释为 QoS 的因果收益。

## 整个进程树

`ps` 按 PID / PPID 递归统计 **daemon 及全部子孙进程**，包括 Git 和缓存历史流尚存的 Git 子进程；不计测试 Node、采样 `ps` 或 Electron。配置每次采样后等待 50 ms，包含 `ps` 开销的实际采样间隔中位数 **77.6 ms**，共 **3750** 个样本。短任务可能没有样本，短命子进程可能漏采；阶段边界附近的样本也可能跨入下一阶段，以下为采样近似峰值。

| 阶段 | 整树 RSS 采样峰值 | 采样数 | 最多进程 |
| --- | ---: | ---: | ---: |
| 初次索引 | 80.73 MiB | 3734 | 4 |
| 活动，30 天 / 90 天 | 未采到 | 0 / 0 | 未采到 |
| 改动，30 天 | 32.83 MiB | 1 | 2 |
| 关注，30 天 | 37.34 MiB | 1 | 2 |
| 改动，90 天 | 43.73 MiB | 1 | 2 |
| 关注，90 天 | 46.91 MiB | 1 | 2 |
| 活动，2 年 | 52.66 MiB | 1 | 2 |
| 改动，2 年 | 65.55 MiB | 1 | 2 |
| 关注，2 年 | 86.61 MiB | 5 | 2 |
| 五轮统计 + 历史对照 | 94.72 MiB | 5 | 2 |

约 4 ms 的空闲历史读取没有独立样本；并发阶段峰值覆盖该次统计的完整运行，不是仅那 4 ms 历史调用的峰值。RSS 随连续查询有增长，单次短测不能据此判断内存泄漏，也不构成长期内存验收。采样还保存全树 `ps %CPU` 之和，它是进程生命期平均值的采样，**不是请求 CPU 耗时或精确瞬时 CPU 占用**，不据此计算查询 CPU 成本。

## 限制与复现

- 本次性能数字来自首批 daemon 对照，测量时桌面尚保留两个非操作额度和分析 615 秒总超时。同日后续已按用户要求同步拆分桌面额度并移除分析总超时，见[验证记录的桌面跟进](../validation/stats-scheduling.md)。没有据此重跑性能；上述数字仍不能冒充 Electron / renderer 性能或实窗验收。
- 未验证其他操作系统、冷历史页 / 深页、并发分析的实际性能、长暂停、持续 CPU 满载、系统休眠 / 唤醒、超过本样本规模的真实仓库在完整索引后的统计性能或 Electron 整树表现。
- 测试与实现细节见[调度验证](../validation/stats-scheduling.md)。完整本机采样及检查日志在忽略目录 `output/benchmarks/stats-scheduling/`；可审阅的耗时、覆盖、结果摘要、各阶段进程树数据保存在[精简 JSON](stats-scheduling-data.json)。

```sh
node tests/benchmarks/stats-scheduling.mjs \
  target/release/commitscope-daemon \
  /Users/huangsheng/Development/prisma \
  /仓库外的新缓存目录 \
  /临时目录/stats-scheduling.json \
  2023-11-28T00:00:00+08:00
```

固定同一 HEAD、同一截止日期与默认排除配置才能比较结果摘要。重复使用缓存目录可跳过已有索引构建；仍会通过 daemon 的完整覆盖状态检查后再计时。
