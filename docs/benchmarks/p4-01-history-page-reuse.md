# P4-01 日期定位页面复用实测

日期：2026-11-09。单次本机定向前后对比，非发布 p95 或长期内存验收。

## 改动与条件

本批在 `2ec7457` 的快速导航之上，减少每次日期定位传输与分配的重复数据。Rust 返回真实目标 OID 和页游标；已载页只回位置，未载页只回页面内容，沿用当前冻结快照的 repository / refs。renderer 命中时保留已有页面、提交与引用数组，不再把整个窗口替换成一页。1800 条摘要上限不变，没有扩大缓存。普通滚动翻页协议没有改变。

- 与上一轮相同的十万提交 / 千引用宽图 fixture，HEAD 为 `d97a306fb4b8b27a1ff8754bd32b45e753cd6c25`；使用同一个完整索引 profile `output/benchmarks/p4-01-profile-20261108`。
- 每次重新启动 release Electron，窗口 1180 × 760。为了排除同期 UI 开发影响，后测在基于 `2ec7457` 的独立临时 worktree 中构建，只同步本批性能文件；文件 SHA256 见下列输入清单。两次测量使用同一布局和操作轨迹，未并行构建或测试。
- 六个不同日期的直接 preload IPC 往返后，额外读取一个种子页面，再用该页游标重复定位三次。时间含请求 / 响应，不含绘制；数据大小是 `JSON.stringify(response.value)` 的 UTF-8 字节数，不是物理 IPC 传输计数。
- 真实滑轨使用相同六小时时间段、24 次指针移动和名义 50 ms 间隔。释放到首次稳定样本用 100 ms 轮询，另作约 310 ms 稳定确认；不能分辨几十毫秒以内的绘制改善。
- RSS 汇总整个 Electron 进程树，可能重复统计共享页。拖动后单点与后续五秒样本不代替空闲预算、峰值或三十分钟检查，未强制 GC。

## 结果

| 项目 | 优化前 | 优化后 |
|---|---:|---:|
| 同页三次定位中位数 | 10.6 ms | 0.5 ms |
| 同页响应大小 | 352,111 字节 | 145 字节 |
| 不同页响应大小 | 352–368 KB | 206–222 KB |
| 后续五个不同日期定位中位数 | 42.3 ms | 32.4 ms |
| 第一次定位（含日期拓扑扫描） | 523.0 ms | 511.0 ms |
| 滑轨释放到首次稳定样本 | 105.0 ms | 103.8 ms |
| 拖动后整树 RSS 单点 | 802.0 MiB | 788.0 MiB |
| 随后第五秒整树 RSS | 769.6 MiB | 755.9 MiB |
| 六秒滚动采到的边缘等待 | 0 ms | 0 ms |
| 滚动时摘要 / DOM 行峰值 | 1800 / 37 | 1800 / 37 |

六对跨页结果的 offset 和完整提交 / 图字段 SHA256 一致；三次同页命中不返回行且目标 OID 一致。实际拖动的最终时间、OID、偏移及可见窗口一致。两版滚动都没有采到等待，未证明更极端滚动下的收益。

内存下降主要在 main：第五秒 main 为 223.5 → 206.1 MiB，renderer 为 372.3 → 376.0 MiB，Rust 为 33.2 → 33.0 MiB。**本批确认了重复传输和同页分配减少，没有确认 renderer 常驻内存下降，500 MiB 目标仍未达到。** 首次扫描约半秒、深页图检查点淘汰与长时资源增长仍待后续处理。该批增加了三次重复请求，不能直接与上一报告的 RSS 数字混作同口径对比。
