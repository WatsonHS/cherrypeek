# P4-01 首批交互查询优化

日期：2026-11-08。本批改善 OID 搜索、消息搜索和首次日期定位，未完成 P4-01 的全部性能及恢复验收。

## 测量条件

- MacBookPro18,3，M1 Pro / 10 核 / 32 GiB，macOS 27.0.1；Electron 45.2.3，release Rust。
- 使用现有宽图参考仓库：100,000 个提交、1,000 条本地引用、8 条长分支和 octopus HEAD；HEAD 为 `d97a306fb4b8b27a1ff8754bd32b45e753cd6c25`。清单见 `output/fixtures/p2-01-wide-graph-20261108/manifest.json`。
- 同一个独立应用数据目录，先完整建立索引，再分别重启优化前 / 后应用。两次测量前已有相同的 78,438,400 字节索引，查询前均确认覆盖 100,000 条且 complete；启动初始状态短暂 queued 不表示重建全部索引。首次建索引的运行仅作准备，不参与 warm 内存比较。
- 前台可见窗口 1180×760，位置、显示器和 main bundle 哈希相同。查询通过真实 preload IPC 串行执行，每种三次；表中时间是 renderer 调用到响应，不含绘制，不是发布验收 p95。
- 空闲采样 15 秒，每 500 ms 用 `ps` 枚举 Electron 的整个子进程树，包括 main、renderer、GPU、utility、Rust、Git。RSS 求和可能重复计算共享页；Playwright 调试连接也有开销。采样可能遗漏短命 Git 进程，短时 CPU 不能代替一分钟验收。

优化前源码 HEAD：`9eb8940c6cf3e5b611bcb3bb4e682efc2c2aadcc`，当时仅文档和测量脚本有未提交改动。优化后为该 HEAD 加本批 `search.rs` / `history.rs` 修改。

## 查询结果

| 场景 | 优化前 ms | 优化后 ms | 口径 |
| --- | ---: | ---: | --- |
| OID 前缀，命中 1 条 | 178.6 | 1.3 | 三次中位数 |
| 消息命中，99,998 条 | 233.4 | 181.0 | 三次中位数 |
| 消息无命中 | 197.1 | 149.9 | 三次中位数 |
| 默认活动统计，100,000 条 | 198.2 | 173.9 | 三次中位数 |
| 日期跳转至 offset 25,000 | 1298.9 | 916.6 | 本进程首次，目标页未缓存 |
| 日期跳转至 offset 12,400 | 1254.7 | 890.5 | 本进程首次，目标页未缓存 |
| 日期跳转至 offset 25,000 | 491.3 / 461.4 | 449.3 / 429.1 | 第二 / 三次，页面已缓存 |
| 日期跳转至 offset 12,400 | 489.5 / 459.3 | 428.2 / 462.0 | 第二 / 三次，页面已缓存 |
| 日期落在 offset 0 | 453.0 | 449.5 | 三次中位数，未观察到明显变化 |
| HEAD 所属分支 | 416.9 | 399.9 | 三次中位数，本批未修改该路径 |

日期输入取自 Git topo 顺序的第 25,000 / 50,000 / 75,000 个位置，但时间并非拓扑单调，实际返回 offset 分别是 25,000 / 12,400 / 0；不能把三次都宣称为深页定位。

OID 查询由原先的全索引行扫描改为现有 `(snapshot_key, oid)` 索引的范围查询。保留时间、身份、消息等交集筛选、部分索引水位和精确计数；SQL 明确指定现有索引，避免 `ORDER BY ordinal` 让 SQLite 选择原先的顺序扫描。消息 / 活动查询减少无筛选时的身份字符串读取，仅解析选中的时间字段；ASCII 消息避免 Unicode case folding，非 ASCII 保持原语义。日期扫描保存命中提交的拓扑序号，直接复用页偏移和图检查点，不再重新按 OID 遍历。

前后 24 对查询均成功、无 BUSY 重试。搜索及日期页完整返回行的 SHA-256、命中数、页偏移和顺序一致，日期行摘要也包括图布局；活动桶数量、作者数量和分支摘要一致。重启后 `resultVersion` 因查询标识包含 session repoId / generation 而变化，比较时仅排除这个会话字段。

## 内存与剩余边界

| 进程树空闲 RSS 中位数 | 优化前 MiB | 优化后 MiB |
| --- | ---: | ---: |
| 整树 | 612.4 | 603.0 |
| Electron main | 202.2 | 201.8 |
| renderer | 222.3 | 213.4 |
| GPU | 84.2 | 84.3 |
| utility | 47.7 | 47.9 |
| Rust | 17.2 | 16.8 |
| Git | 35.8 | 35.8 |

各角色中位数并非同一时刻，不要求相加等于整树中位数。空闲 RSS 采样发生在手动查询之前，本批没有修改 Electron；约 9 MiB 的变化主要来自 renderer，不能归因于查询修正。500 MiB 目标仍未达到。main JS heapUsed 约 12–13 MiB，renderer 约 15–17 MB，整树 RSS 不能用 JS 堆替代。

15 秒窗口中观测 CPU 增量为 0.80 / 0.38 秒；不据此宣称一分钟空闲 CPU 达标。首屏单次观测 2233 / 1898 ms，也不据此宣称冷 / 热启动 p95 达标。日期页缓存命中后仍需要日期遍历；本批未优化包含分支、索引构建或全量路径搜索。30 分钟运行、完整发布样本和异常恢复仍待后续 P4-01。

## 复现与证据

```sh
node scripts/benchmark-interactive.mjs \
  --repository=/absolute/path/to/wide-history \
  --profile=/absolute/path/to/performance-profile \
  --output=/absolute/path/to/new-result.json \
  --idle-ms=15000 --queries=3
```

先用同一 profile 跑一次完成索引准备，再对优化前后各重启运行；每次输出使用新路径。测量期间不并行构建和运行其他项目测试。

本机原始证据保存在 `output/benchmarks/`：

- `p4-01-fresh-20261108-2.json`：首次建索引准备；其旧进程角色分类把 utility 算入 renderer，分角色值不用于正式比较。
- `p4-01-before-warm-20261108.json` / `p4-01-after-warm-20261108.json`：正式前后测量。
- `p4-01-comparison-20261108.json`：24 对查询事实摘要比较。
- `p4-01-fresh-20261108.json`：脚本初版初始化错误，未启动应用，不作为基线。

受影响检查：search 单测 9 项、history 单测 11 项、搜索集成 4 项（独立 Git 对照、部分索引、取消、SHA-256）通过；release 构建成功。未扩展运行整套平台或发布矩阵。
