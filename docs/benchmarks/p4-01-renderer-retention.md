# P4-01 连续导航的分配与内存

日期：2026-11-09。单次本机定向比较；不代表发布 p95 或三十分钟验收。

测量后的预算修订：用户同意放宽 500 MiB 目标，本轮采用空闲整树 RSS 800 MiB、交互阶段 1 GiB 观察目标，见 [VALIDATION](../VALIDATION.md)。本文的 500 MiB 结论保留为测量时口径，不再是当前阻塞项；实测数字不变。

## 条件与诊断

前后以 `d69c22d` 为基准使用独立构建，同一十万提交 / 千引用 fixture、完整索引 profile、1180 × 760 窗口。Rust 二进制未改动，复用其 release 产物；桌面代码分别重建。同期 P4-09 的 UI 与接口接线没有混入测量。

先执行原导航测量：六个日期、三次同页请求、一次真实滑轨拖动、五秒内存采样和六秒滚动。此阶段没有堆快照或主动 GC，RSS 统计整个 Electron 进程树。之后才进入独立诊断阶段：取快照，采样三轮相同的拖动 / 滚动 / 回到最新，最后再取快照。分配采样间隔 32 KiB，计入已被回收的对象，数字为采样估算。每轮滚动按六秒计时，事件往返使前后事件数有少量差异。

优化前后各自三轮操作的快照均显示：历史提交和图对象维持 2600 个，DOM 节点回到 1476，监听器回到 394，标记 detached 的节点维持 38 个。统计涵盖整个 renderer 堆及 IPC 副本，不等同于 store 的活动窗口。没有看到这些对象随三轮操作持续累积；没有据此认定长时无泄漏。快照可能触发 GC，分析器自身还会显著抬高 RSS，**诊断阶段 RSS 不参与正常内存对比**。

最大的业务分配热点来自关闭的分支菜单：`ScopePicker` 每次随历史状态更新，仍为约千条引用创建 JSX。其次是 `refsByTarget` 对同目标引用逐次展开整个数组，以及普通页面重复传入 renderer 的引用数据。

## 实现与结果

只在菜单打开时构造内容；引用索引使用本次新建的 bucket 追加；普通分页以 `contentOnly` 模式从 main 返回提交页，renderer 补上当前快照的 repository / refs 并保持对象身份。Rust → main 的响应与校验保持原样；首屏、刷新、范围切换依旧读取完整上下文。没有扩大缓存或引入对象池。

| 项目 | 优化前 | 优化后 |
|---|---:|---:|
| 三轮操作 JS 分配采样估算 | 1010.5 MiB | 613.6 MiB |
| 拖动后正常整树 RSS 单点 | 780.2 MiB | 757.3 MiB |
| 随后第五秒整树 RSS | 748.4 MiB | 729.0 MiB |
| 第五秒 renderer RSS | 368.5 MiB | 349.7 MiB |
| 同页定位中位数 | 0.4 ms | 0.4 ms |
| 五个后续不同日期定位中位数 | 40.4 ms | 42.8 ms |
| 首次日期定位 | 522.8 ms | 537.0 ms |
| 拖动释放到首次稳定样本 | 103.8 ms | 103.6 ms |
| 滚动摘要 / DOM 行峰值 | 1800 / 37 | 1800 / 37 |

分配估算减少约 39%，正常整树 RSS 少约 19–23 MiB。定位速度没有显示改善；首次扫描仍约半秒。两版滚动都未采到边缘等待，不能宣称极端滚动达标。

额外对同一个第二页做完整 / 内容模式的真实 IPC 对照：200 条记录及所有图字段相同，响应 value 的 UTF-8 JSON 从 **368,301 降至 221,678 字节**（约少 40%）。该值仅代表 main → renderer 业务数据，不是物理 IPC 字节计数。六对日期页的 offset 与完整行 SHA256 一致，真实滑轨最终时间、OID 和窗口一致。菜单打开显示 1000 条引用，点击外侧可以关闭。

**500 MiB 目标仍未达到。** 本批证明关闭菜单的重复构造和翻页分配得到减少，未证明全部内存增量来自泄漏，也未完成长期稳定性或所有仓库验收。本轮基准已包含新的页面切换 UI，不能与上一轮报告的绝对 RSS 直接混作同口径比较。

## 检查与证据

受影响会话状态 38 项、独立构建与主工作区 TypeScript 检查通过，最终主工作区 release 构建也通过。该集成构建包含同期 P4-09 接线，不作为隔离测量对象。测试覆盖内容模式、引用对象保持、前后翻页、1800 条淘汰、取消、刷新及过期响应。本批未改 Rust，不额外运行核心全量测试。真实菜单与 IPC 对照并入后测末尾，不影响先前的性能采样。

原始证据位于 `output/benchmarks/`（忽略目录）：

- 前测 `p4-01-retention-before-fixed-20261109.json`，后测 `p4-01-retention-after-20261109.json`；其同名前缀下保存 `.before.heapsnapshot`、`.after.heapsnapshot` 和 `.allocations.json`。
- 构建输入哈希 `p4-01-retention-build-inputs-20261109.json`；有跟踪源码的差异 `p4-01-retention-changes-20261109.patch`。完整 main / daemon / renderer 哈希在测量 JSON 中。
- 摘要对照 `p4-01-retention-comparison-20261109.json`。
- 最初 `p4-01-retention-before-20261109.json` 因新增页面切换按钮与列表共享“提交”标签，脚本选择到了按钮而超时。已将选择器限定为 listbox，该失败样本未用于结果。

复现沿用[快速导航报告](p4-01-fast-history-navigation.md)的测量命令，增加 `--retention=true` 进入诊断和针对性 UI / IPC 检查。默认不做堆快照。输出路径必须尚不存在；任何失败均保留证据并标记失败。
