## 当前性能预算

参考机器确认为 Apple M1 Pro / MacBookPro18,3、10 核、32 GiB、1 TB 本地 SSD、macOS 27.0.1。运行时基线为 Electron 45.2.3 / 内嵌 Node 24.22.2 / Chromium 156.0.8078.80，构建 Node 26.0.0 / Rust 1.95.0；版本更新后另记结果。单个活跃仓库，发布关卡使用打包 release。滚动关卡固定 60 Hz；当前主屏为 120 Hz，外接屏有 60 / 120 Hz，本次 headless 实验未测滚动。M0 的 release 工程构建不代替安装包验收。Windows 单独建基线，不直接套用 macOS 数据。

| 指标 | 当前目标（10 万提交参考集） | 测量口径 |
| --- | --- | --- |
| 无应用缓存的首屏 | p95 ≤ 3 秒 | 从进程启动到 200 条真实提交可选择，索引未建；不称 OS 磁盘冷缓存 |
| 有缓存的首屏 | p95 ≤ 1.5 秒 | 应用重启，复用索引 / 缓存；仍从进程启动计时 |
| 普通翻页 | p95 ≤ 200 ms | 请求下一页到绘制完成，页大小 200 |
| 完整元数据搜索 | p95 ≤ 200 ms | 索引完整、引用快照有效，代表性 OID / 作者 / 消息查询；包含 IPC 和绘制，不含输入防抖 |
| 路径搜索 / 无索引搜索 | 首批结果目标 ≤ 1 秒 | 全量完成另记耗时；超过预算仍保持可取消，不能把部分结果算作全部 |
| 输入和取消反馈 | 100 ms 内可见反馈；后台取消目标 ≤ 500 ms | UI 与子进程分别记录，长任务不拖慢新查询 |
| 普通文本 diff | p95 ≤ 300 ms | 单个 ≤ 1 MiB 文本的按需展示；极端长行、大文件单列结果 |
| 连续滚动 | 60 Hz 下 p95 帧间隔 ≤ 20 ms，无超过 100 ms 的可见卡顿 | 固定 30 秒滚动轨迹；记录掉帧、主线程长任务及图绘制成本 |
| 空闲进程树 RSS 总和 | 目标 ≤ 800 MiB | 索引完成、打开历史且无 diff；main / renderer / GPU / utility / Rust / Git 全部计入 |
| 交互阶段进程树 RSS 总和 | 观察目标 ≤ 1 GiB | 同一完整索引参考集的滚动、日期跳转、搜索和普通 diff；记录采样峰值，超出先定位原因，不新增独立阻塞门槛 |
| 空闲 CPU | 一分钟平均 < 1% 单核等价 | 索引完成后静置，持续后台检查同样计入 |
| 外部更新提示 | 正常通知 p95 ≤ 1 秒；可见窗口兜底目标 ≤ 5 秒 | 从外部引用更新到有更新提示；不包含等待用户点击刷新，休眠时不计 |

对缺少三字符的中文短词、常见超多命中词和冷路径搜索分组报告；若需要扫描，不套用已完整索引普通查询的 200 ms 结论。精确统计首次完成时间、索引耗时、磁盘增长、深页回读、搜索新批次合并与锚点恢复延迟、点击刷新后新快照可交互时间和峰值内存都要记录，即使本轮尚未设硬预算。更新通知延迟不能当作刷新完成延迟。

### 2026-11-09 内存预算调整

用户要求：500 MiB 目标难以达到时可以放宽。本轮采用空闲整进程树 RSS 800 MiB、交互阶段 1 GiB 观察目标，替代旧的 500 MiB 空闲目标。此前几轮已减少重复查询、传输与 UI 分配；最新十万提交测量的拖动后整树 RSS 为 757.3 MiB、随后第五秒为 729.0 MiB，继续压低到 500 MiB 的优先级让位于实际功能与日用体验，见[分配与内存报告](benchmarks/p4-01-renderer-retention.md)。

这些短时样本处于新目标内，但不能据此宣布空闲、交互峰值或发布关卡全部通过。仍要求有界缓存、正常交互流畅，以及 30 分钟运行不持续增长；统计口径不变，不靠强制 GC 验收。旧报告中的“未达到 500 MiB”保留为当时结论，不再作为当前阻塞项；首次索引、百万提交压力及堆快照诊断分别报告，不混入上述交互预算。

## 怎么测

1. 记录代码版本、依赖版本、机器配置、仓库状态、缓存条件和后台负载；关闭开发者工具，使用 release 包。
2. 首屏区分无应用缓存 / 有应用缓存，说明是否控制了 OS page cache。每种启动条件至少 10 次，报告每次与中位数；发布关卡补到 30 次并计算 p95。搜索和翻页每组至少 30 次，混合命中、无结果及频繁切换。
3. 埋点分解 Rust 读取、队列等待、序列化、IPC、React 提交与可见绘制，保留端到端时间。不会以某个内部函数快来代表用户体验快。
4. 统计整个进程树，明确 CPU 百分比换算方式。RSS 总和可能重复计入共享页，只作为固定口径比较；同时记录平台可用的 footprint / private memory，不能跨平台混称同一指标。
5. 用固定操作轨迹运行 30 分钟：滚动、换仓库、查询、看 diff、外部提交、再空闲。记录垃圾回收后的稳定区间与增长趋势，不以瞬时峰值回落证明无泄漏。
6. 若对照其他客户端，使用同仓库、同操作、同冷暖条件和相同进程树口径；明确版本与功能差异。尚未运行时不写“比 JetBrains / GitComet 更快或更省内存”。

## 正确性与恢复关卡

- **查询集合**：fixture 中预先声明预期 OID / 父关系 / 文件变化，以独立 Git 命令交叉检查。不要复用被测适配器本身生成预期结果。验证全部分页的集合、稳定顺序和去重。
- **搜索语义**：消息框只匹配标题与正文，不匹配仅出现在作者 / 邮箱 / OID 中的相同文本；看似 hash 的消息输入仍按消息搜索。hash 筛选独立验证缩写歧义。覆盖字段间 AND、同一身份字段多选 OR、Author 与 Committer 区别、大小写开关和索引 / 扫描一致性。
- **部分结果**：控制扫描顺序，使后到的命中应排在前面，并覆盖同时间戳的 OID 次序、无命中阶段和跨页边界。每批自动去重和排序后，所选 OID、视口顶部 OID 与行内偏移保持；不同结果版本的页不混接，renderer 保留行数有界。完成前持续显示部分结果或“尚未找到，搜索中”，完整后结果集合与独立预期一致。
- **路径与 merge**：分别构造仅相对第一父提交、仅相对第二父提交有变化的样例；查询结果与所选 diff 的父提交标注一致。
- **统计**：同一 commit 被多个分支包含只计一次；按当前浏览快照、全部有效筛选条件、指定时间字段和时区独立计算预期数量。部分索引和未完成扫描不得呈现精确最终总数；历史、搜索与统计不混用快照或筛选。按 Author 的分布按原始姓名与邮箱独立分组计数，并与总数一致。
- **引用关系**：基准按 origin/HEAD → origin/main → origin/master 解析，没有远端跟踪分支时退回本地 main → master；切换任一 worktree 的 HEAD 不改变基准，外部 fetch 更新 origin/main 后只在刷新到新快照时重新计算。合入状态的可达判断与独立 `git merge-base --is-ancestor <分支> <基准>` 一致，MVP 中不可达的分支不显示标签；M4 加入补丁比对后，与独立 `git cherry` / `git patch-id` 一致，fixture 分别覆盖普通 merge、squash、rebase、cherry-pick 合并，以及合并时改过内容的 squash（应不显示标签而非误判）；比对超限或未完成时不出现否定结论，也不触发仓库写入。“包含它的分支”与独立 `git branch --contains` / `git branch -r --contains` 一致。两者都绑定当前浏览快照、可取消，外部引用变化不改写已显示的结果。worktree 检出标注与 `git worktree list --porcelain` 一致。
- **上次查看与更新明细**：“上次查看后新增”与独立 `git rev-list <当前 tips> --not <上次 tips>` 一致，覆盖新增提交在拓扑顺序中不连续的情况（只标圆点、不画分隔线）；上次记录缺失或损坏时不标记、不报错。更新明细的快进 / 改写分类与独立 `git merge-base --is-ancestor <旧> <新>` 一致，被替换数与 `git rev-list <旧> --not <新>` 一致，新建与删除不遗漏；查看明细不改变当前浏览状态。
- **交给 Agent**：prompt 中的观察时间、OID、领先 / 落后数与独立 `git rev-list --left-right --count` 一致，两侧改动文件与独立 `git diff --name-only <分叉点> <各侧尖端>` 的交集一致。用含“忽略之前要求”等伪指令、含伪造分隔标记的提交标题、分支名和路径做 fixture，确认它们只出现在参考数据段内且分隔标记无法被提前闭合；全部仓库名称与列表仅在序列化参考数据中出现，正文编号均可解析。覆盖当前 worktree 与浏览分支不一致、多条 prunable 记录、三父 merge、空仓库、detached、无基准和未知计数；prune 不扩大目标集合。复制前后仓库快照不变，复制动作不启动新进程；取事实可启动受约束的只读 Git。
- **详情扩展**：trailer 解析与 `git interpret-trailers --parse` 一致，正文中间形似 trailer 的行不被拆出；merge 带入的提交与独立 `git rev-list <第 N 父> --not <第一父>` 一致，octopus 按父提交分组。
- **竞态**：人为延迟旧查询，依次切换筛选、仓库并主动刷新快照；被替代请求的响应不能覆盖新状态。仅收到外部新快照通知时，当前浏览请求的响应仍须正常接收。搜索定位与返回保留原范围、快照、查询和锚点；覆盖后续加入的路径筛选。
- **固定快照与刷新**：外部提交间隔短于一次完整搜索 / 统计所需时间，验证当前快照查询仍能完成，不反复取消，也不自动混入新提交。点击刷新后统一采用新快照；保持有效的选择与锚点，锚点或所选引用失效时明确提示。另测无关分支更新不打断查询。
- **改写与缺失**：rebase / amend 后旧浏览快照保留并提示有更新；主动刷新后失去可达性的提交退出新范围，已读详情可保留且标明状态。GC 删除固定快照所需对象后显示失效 / 不完整，不自动补拉，不宣称查询完整。不能用时间戳增量策略漏掉旧日期的新 OID。
- **只读**：对 fixture 的工作区、index、HEAD、refs、配置和相关 Git 文件做前后快照；没有无关写入。外部执行哨兵未触发，无外部网络访问 / lazy fetch。
- **协议与资源**：超长消息、截断帧、取消、daemon 崩溃、磁盘满、SQLite 中断 / 损坏有明确恢复；关闭仓库或退出应用无残留任务和 Git 子进程。
- **平台交互**：中文输入法（组词期间不触发快捷键和命令面板）、键盘焦点、分支图超过 6 条线时的“+n”提示、（M4）窄窗口布局与分支图拖宽、系统缩放、Finder / Windows 桌面启动、带空格 / 非 ASCII 路径和睡眠恢复通过实际验证。
